## 3. 🔴 重点缺口：跨模型（多模型）治理

**现状（已核实）**：
- `semantic_quality_checker.py::_check_consistency` 的所有"一致性"检查（重名 `CON_NAME_DUPLICATE`、重复表达式 `CON_DUPLICATE_METRIC_EXPRESSION`、表关系重复/自连/循环）都发生在**单个 config 内部**；
- 质量体检 `quality-check.md` 明确"评估**当前语义模型**"；查询约束"一次调用只用一个 `semantic_config_id`"；
- 尽管 `workspace/semantic/` 已物化数据源组内**多份** YAML，但**没有任何跨模型横向比对**。

**多模型治理应分析的 7 项：**

1. **同指标跨模型口径比对（核心）**：同名/经别名识别为同一业务指标，在不同模型中的公式表达式、统计周期、过滤条件、去重逻辑、维度、单位、数据源是否一致 → 输出"口径一致 / 口径冲突清单（A 口径 vs B 口径 + 差异点）"。
2. **重复 / 同义指标识别**：语义相同但命名不同（别名重复建设）；命名相同但语义不同（最危险，需预警）。
3. **维度/字段定义一致性**：同名字段的类型、枚举集合、含义是否一致；时间/机构/渠道等公共维度跨模型统一。
4. **命名规范一致性**：前缀、缩写、中英文、大小写、业务术语使用是否统一（对接术语表/标准）。
5. **覆盖与重复建设分析**：指标×模型分布矩阵、模型间指标重叠度、孤儿指标、跨源同义表重复建模。
6. **跨模型血缘/来源**：同一指标在不同模型依赖的物理表是否同源；不同源却同名是否合理（依赖血缘，可后置）。
7. **指标体系收口建议**：识别应下沉为全局/公共的指标，给出"以哪个为准 / 新建统一指标"建议。

**实现形态（结合现有底座，仅方向）：**
- 输入现成：`workspace/semantic/` 已物化组内多份 YAML；先做"**同组内多模型**"，跨组需多组物化与授权。
- 新增跨模型比对服务（如 `services/semantic/run/cross_model_consistency_service.py`）：解析多份 config → 指标/维度归一化（名称+别名+表达式指纹）→ 对齐匹配 → 确定性逐项比对 → 差异矩阵。
- 确定性优先（表达式归一化、命名指纹、类型/枚举比对）；"是否同一指标/口径是否等价"等语义判断由 LLM 辅助（复用 `get_chat_data_llm`），结论结构化、可复核。
- 技能层在 `references/governance/` 新增"跨模型一致性检查"流程，与现有单模型 `quality-check` 区分。

**框架定位**：对应 DAMA 数据标准（指标标准）、元数据、跨系统一致性；本质是"**同一个指标、同一个口径（SSOT）**"，属于指标体系治理，而非单模型质检。

## 4. 补齐优先级建议（契合"先扎实最小闭环、再扩展"）

**近期（强化现有治理闭环，性价比最高）**
1. 跨模型一致性检查（同指标口径比对、重复/同义指标、维度冲突）——多份 YAML 已物化，输入现成，直击"同指标不同口径"。
2. 轻量业务术语表/数据标准库 + 命名规范落地检核。

**中期**
3. 真正面向数据的数据质量检核（空值/唯一/枚举/波动规则，复用现有查询执行底座）。
4. 字段级血缘 + 影响分析（sqlglot PoC 产品化）。
5. 元数据自动采集 + 数据地图/资产目录。

**远期（平台化、跨部门）**
6. 主数据/参考数据、分类分级与脱敏、生命周期、资产估值/数据服务市场、治理工单与整改流程。
