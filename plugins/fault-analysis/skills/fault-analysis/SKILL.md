# 故障分析

## 定位与边界

本技能做**只读诊断**：收集现象、复现问题、定位根因、给出处置建议。不做任何写操作——
不修改语义模型配置、不更新数据源、不调整调度任务；需要变更时在结论中列出建议动作，
交由用户或管理员确认后执行。

## 工作流程

按四步推进，每一步的详细操作读取对应能力文档；不要预读全部资料。

| 步骤 | 目标 | 能力文档 |
|---|---|---|
| 1. 收集现象 | 明确故障表象、时间点、影响范围、已尝试的操作 | `references/triage.md` |
| 2. 分层定位 | 按链路层（SQL 执行 → 数据源 → 语义口径 → 调度链路）逐层收敛 | `references/triage.md` |
| 3. 佐证结论 | 用可复查的证据（错误信息、SQL、行数对比、时间线）支撑根因判断 | — |
| 4. 输出结论 | 按"结论先行"格式给出根因、证据、影响范围、处置建议 | — |

一次分析只针对一个主问题。用户给出多个故障时，先和用户确认优先处理哪一个。

## 分层定位顺序

从下往上排查，先排除底层故障再怀疑上层口径：

1. **SQL 执行层**：报错信息、超时、被拦截的 SQL guard、方言不兼容；
2. **数据源层**：连接健康、表/字段存在性、数据量突变、分区缺失；
3. **语义口径层**：指标表达式、维度映射、时间口径（T+1/实时）、过滤条件；
4. **调度链路层**：任务是否成功、依赖上游是否延迟、物化表是否按时产出。

大多数"数据对不上"是口径问题（第 3 层），大多数"跑不出来"是执行或调度问题
（第 1、4 层）；先确认现象属于哪一类再深入，避免全链路盲扫。

## 输出格式

```text
【结论】<一句话根因判断，按置信度标注：确认 / 高度怀疑 / 待验证>
【现象】<故障表象与影响范围>
【证据】<支撑结论的可复查证据，逐条列出：错误信息 / SQL / 数据对比 / 时间线>
【根因】<分层定位到的具体环节与原因>
【建议】<处置动作，标注由谁执行：用户自行处理 / 需要管理员 / 需要数据侧修复>
【遗留】<本次未能确认的疑点，及下一步验证动作>
```

证据不足时明确说"待验证"并列出需要的信息，不要用猜测填充结论。
