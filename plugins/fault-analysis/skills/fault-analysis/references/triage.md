# 分层排查手册

## 第 1 层：SQL 执行层

典型现象：接口报错、SQL 执行异常、超时、结果为空。

排查要点：

- **报错信息**：拿原始错误文本分类——语法错误（方言问题）、权限拒绝、对象不存在、资源超限；
- **SQL guard 拦截**：确认是否被白名单/limit 注入校验拦截，拦截信息会说明具体规则；
- **超时**：区分语句级超时与连接级超时；大表全扫、笛卡尔积、深分页是常见原因；
- **结果为空**：确认过滤条件是否过严、时间范围是否落在空分区。

## 第 2 层：数据源层

典型现象：同一 SQL 时好时坏、数据量突变、字段值异常。

排查要点：

- **连接健康**：数据源是否可达、连接池是否耗尽、近期是否有网络变更；
- **对象存在性**：表/字段是否被重命名或下线；
- **数据突变**：对比近期行数/关键指标的趋势，识别是否上游产出异常；
- **分区与时间**：分区是否按时产出、目标日期是否有数据。

## 第 3 层：语义口径层

典型现象："数据对不上"、同比环比异常、不同入口结果不一致。

排查要点：

- **指标表达式**：聚合方式（SUM/COUNT/DISTINCT）、去重口径、是否含排除条件；
- **时间口径**：T+1 还是实时、统计窗口（自然日/滚动）、时区处理；
- **维度映射**：维度字段是否正确关联、是否存在枚举值变更；
- **过滤条件**：状态过滤、删除标记、测试数据是否被正确排除。

定位方法：把口径拆成"过滤 → 关联 → 聚合 → 计算表达式"四段，逐段用最小 SQL 验证，
找出与预期不符的第一段。

## 第 4 层：调度链路层

典型现象：例行报表缺数、更新延迟、上游依赖失败。

排查要点：

- **任务状态**：目标任务最近一次执行是否成功、耗时是否异常；
- **依赖上游**：上游任务是否延迟/失败，故障是否沿依赖链传播；
- **物化产出**：物化表/结果表的产出时间与数据日期是否符合预期。

## 证据收集清单

输出结论前，逐项确认手头是否有以下证据；缺哪项就明确说"待验证"：

- [ ] 原始报错信息（完整文本，不截断）
- [ ] 出错的 SQL（或产生数据的那条 SQL）
- [ ] 涉及表/字段的元信息（行数、分区、最近更新时间）
- [ ] 故障发生时间线（首次出现、频率、最近一次正常时间）
- [ ] 影响范围（哪些报表/入口/用户受影响）
