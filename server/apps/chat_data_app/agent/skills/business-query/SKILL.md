# 业务问数知识技能

## 适用目标

当用户问题涉及业务数据查询、业务对象识别、明细与汇总选择、趋势排行、同名指标多来源冲突、指标可聚合性判断时，使用本技能。

本技能只帮助理解业务问题和规划查询路径。实际能否查询、如何生成 DSL/SQL，必须以当前语义配置中的真实指标、维度、枚举、日期格式、单位和关系为准。

## 使用边界

- 只把技能当作业务判断材料，不把技能当作可执行配置。
- 本技能是知识技能，不是 workflow 技能；不定义智能问数主流程，不编排文件、脚本、artifact 或沙箱。
- 不能编造指标、维度、枚举、表、字段或 SQL。
- 不能绕过系统提示词定义的语义层工具链；智能问数必须继续走 DSL。
- 不能用技能规则覆盖当前指标集的真实配置。
- 当前指标集缺少必要指标、维度、枚举、时间格式、单位或口径时，必须追问或说明不支持。
- 智能问数只读加载本技能时，不使用 file_read，不读取路径，不执行脚本，不使用 assets。

## 领域组织

本技能用一个主入口管理多个业务领域。领域知识放在 `references/<domain>/` 二级目录下，通用问数规则放在 `references/common/` 下。

当前内置领域：

- `prepaid-fund-supervision`：备付金非现场监管领域。
- `order-analysis`：订单、商品、销售和用户成交分析领域。

后续新增业务领域时，优先新增二级目录，不新增默认技能名。

## 两阶段加载

### 指标集选择前

未手动选择指标集时，如果用户问题明显属于本技能覆盖的问数领域，先加载：

- `common/query-routing`：指标集路由知识，用于理解业务领域、明细/汇总/预聚合方向和选择工具 query 写法。

读取路由知识后，仍必须调用指标集选择工具从真实指标集中选择，不能由技能直接决定指标集。

### 指标集选择后

获得唯一指标集后，再根据指标集名称、描述、指标和维度判断业务领域，按需加载：

- `common/query-policy`：通用问数策略，用于 DSL 规划前的业务检查。
- `prepaid-fund-supervision/business-context`：备付金非现场监管业务背景。
- `prepaid-fund-supervision/data-sources`：该领域数据来源、口径层级和同名指标处理。
- `prepaid-fund-supervision/examples` 只在需要参考典型问法时按需加载。
- `order-analysis/business-context`：订单销售分析业务背景。
- `order-analysis/data-sources`：订单、商品、类目、用户和销售指标的数据来源与口径。
- `order-analysis/examples` 只在需要参考典型问法时按需加载。

## 知识检查项

使用本知识技能时，应辅助判断：

1. 用户问题是明细、聚合、趋势、排行、对比还是概念解释。
2. 用户说的是哪个业务领域、业务对象、数据来源或口径层级。
3. 当前语义配置是否包含真实指标、维度、枚举、时间、单位和关系。
4. 问题更接近明细口径、汇总口径、预聚合口径还是监管报表口径。
5. 指标可聚合性：可加、快照、比率、均值、不可二次聚合。
6. 是否存在同名、多来源、多粒度冲突。
7. 能确定则回到系统主流程生成 DSL；不能确定则先追问一个最关键的不确定点。

## 判断完成标准

完成查询规划前，必须能回答：

- 用户要明细还是聚合？
- 是否需要趋势、排行或对比？
- 用户问题属于哪个业务领域、业务对象、数据来源或口径层级？
- 是否缺少时间范围或业务口径？
- 指标是否允许当前粒度下的聚合？
- 同名指标是否存在多来源、多粒度或多口径冲突？
- 当前语义配置是否真的包含所需指标和维度？
