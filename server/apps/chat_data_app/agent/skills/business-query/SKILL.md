# 业务问数知识技能

## 适用目标

当用户问题涉及业务数据查询、业务对象识别、明细与汇总选择、趋势排行、同名指标多来源冲突、指标可聚合性判断时，使用本技能。

本技能只帮助理解业务问题和规划查询路径。实际能否查询、如何生成 DSL/SQL，必须以当前语义配置中的真实指标、维度、枚举、日期格式、单位和关系为准。

## 使用边界

- 只把技能当作业务判断材料，不把技能当作可执行配置。
- 本技能是知识技能，不定义智能问数主流程，也不替代系统工具协议。
- 不能编造指标、维度、枚举、表、字段或 SQL。
- 不能绕过系统提示词定义的语义层工具链；智能问数必须继续走 DSL。
- 不能用技能规则覆盖当前指标集的真实配置。
- 当前指标集缺少必要指标、维度、枚举、时间格式、单位或口径时，必须追问或说明不支持。

## 领域组织

本技能用一个主入口管理多个业务领域。领域知识放在 `references/<domain>/` 二级目录下，指标集选择前的路由知识放在 `references/common/` 下。

每个业务领域使用一个二级目录，目录下保留 `business-context.md`。后续新增业务领域时，只新增领域目录、领域业务背景和必要路由规则，不需要修改主技能说明或新增默认技能名。

## 两阶段加载

业务问数链路只要开始处理数据查询、指标/维度询问或可查询范围概览，先读取本主说明，再按下面规则决定是否继续读取 reference。

### 指标集选择前

未手动选择指标集时，如果用户问题明显属于本技能覆盖的问数领域，先加载：

- `common/query-routing`：指标集路由知识，用于理解业务领域、明细/汇总/预聚合方向和选择工具 query 写法。

读取路由知识后，仍必须调用指标集选择工具从真实指标集中选择，不能由技能直接决定指标集。

### 指标集选择后

获得唯一指标集后，再根据指标集名称、描述、指标和维度判断业务领域，按需加载：

- `<domain>/business-context`：当前领域的业务对象、术语和时间概念。

## 领域 reference 路由

命中领域时只加载对应 reference，不加载无关领域文档；reference 只用于理解业务背景，不能覆盖当前指标集中的真实指标、维度和口径。

- 用户问题、当前可见指标集目录、已选指标集名称/描述、指标名或维度名出现“备付金、分户账、分类账、分类帐、非现场监管、监管报表”等词时，必须读取 `prepaid-fund-supervision/business-context`。
- 用户问题、当前可见指标集目录、已选指标集名称/描述、指标名或维度名出现“订单、销售额、销量、商品、类目、成交、用户购买”等词时，读取 `order-analysis/business-context`。

## 知识检查项

使用本知识技能时，应辅助判断：

1. 用户问题是明细、聚合、趋势、排行、对比还是概念解释。
2. 用户说的是哪个业务领域、业务对象、数据来源或口径层级。
3. 当前语义配置是否包含真实指标、维度、枚举、时间、单位和关系。
4. 问题更接近明细口径、汇总口径、预聚合口径还是监管报表口径。
5. 指标可聚合性：可加、快照、比率、均值、不可二次聚合。
6. 是否存在同名、多来源、多粒度冲突。
7. 能确定则回到系统主流程生成 DSL；不能确定则先追问一个最关键的不确定点。

## 判断完成标准

完成查询规划前，必须能回答：

- 用户要明细还是聚合？
- 是否需要趋势、排行或对比？
- 用户问题属于哪个业务领域、业务对象、数据来源或口径层级？
- 是否缺少时间范围或业务口径？
- 指标是否允许当前粒度下的聚合？
- 同名指标是否存在多来源、多粒度或多口径冲突？
- 当前语义配置是否真的包含所需指标和维度？
