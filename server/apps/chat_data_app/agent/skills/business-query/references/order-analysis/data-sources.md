# 订单销售分析数据来源

## 数据来源分层

订单销售分析通常包含以下数据来源：

- 订单主表：订单级别信息，如订单编号、用户、订单状态、下单时间、支付时间、订单金额。
- 订单明细表：订单商品行级别信息，如商品、数量、明细销售额、成交单价。
- 商品和类目表：商品分类、父类别、层级、启用状态、类别描述等基础维度。
- 用户表：用户属性、用户数量、购买用户等相关维度或指标。
- 汇总或预计算表：按日期、商品、类目、用户或机构等粒度加工好的销售额、销量、订单数、均价等指标。

模型不能只凭表名或字段名判断真实口径。能否查询必须回到当前语义配置确认。

## 选择原则

- 用户要订单列表、明细、具体订单、订单商品行时，优先考虑订单主表或订单明细口径。
- 用户要销量、销售额、商品排行、类目分布、趋势时，优先考虑已维护的聚合指标或可安全聚合的明细指标。
- 用户按商品分类、父类目、层级分组时，需要当前指标集提供对应类目维度或已维护关系。
- 用户按“今天、昨日、本月、上个月同一天”查询时，需要明确时间维度和日期格式。
- 预计算指标如果已经按日期或类目聚合，继续上卷前必须确认粒度不会重复计算。

## 指标口径注意

- 销量通常可加，但必须确认是否按订单明细粒度统计，是否排除取消、退款或未支付订单。
- 销售额通常可加，但必须确认是否含优惠、退款、取消订单、税费或运费。
- 订单数量通常应按订单编号去重，不能用明细行数替代。
- 用户数量通常应按用户去重，不能用订单数替代。
- 平均成交单价、销售额平均值、占比、转化率等均值或比例类指标不能直接二次平均，除非当前语义配置明确了加权规则。

## 时间对比

“今天和上个月同一天”的查询通常要拆成两个基础查询：

- 当前日期，例如 `2026-06-20`。
- 上个月同一天，例如 `2026-05-20`。

如果两个查询返回空值或 null，只能说明当前查询没有返回数据，不能把 null 当成 0，除非语义配置或业务规则明确要求按 0 处理。

## 日期字段

如果语义配置已经把日期字段转换为标准展示格式，应使用转换后的维度口径和筛选值。

如果语义配置没有维护日期格式和转换口径，不能根据列备注或字段名自行假设 `yyyyMMdd`、`yyyy-MM-dd`、时间戳等存储格式。
