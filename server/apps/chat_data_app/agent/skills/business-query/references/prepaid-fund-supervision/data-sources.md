# 备付金非现场监管数据来源

## 数据来源分层

当前业务通常包含三类数据：

- 机构基础信息：机构、账户、银行、地区、类型、状态等基础维度。
- 机构上报数据：机构按监管要求上报的明细或周期数据。
- 数仓加工数据：数仓人员基于上报数据加工出的汇总、监管报表或预计算结果。

模型不能根据表名或字段名自行推断真实口径。能否查询必须回到当前语义配置确认。

## 选择原则

- 用户要“明细、列表、逐笔、上报记录、具体某条数据”时，优先考虑原始上报或明细口径。
- 用户要“汇总、统计、趋势、排名、监管报表、月报、季报”时，优先考虑加工汇总或预计算口径。
- 用户需要按机构属性筛选或分组时，需要确认当前口径是否已经包含机构基础信息，或语义配置是否维护了可用关系。
- 用户指定的筛选维度在预聚合口径中不存在时，不能硬查，应换更细粒度口径或请用户确认。

## 指标口径维护

同名指标可能同时出现在上报表和预聚合表中。处理时必须看：

- 数据来源：原始上报、加工汇总、预计算或监管报表。
- 粒度：逐笔、账户、机构、日、月、季、年。
- 统计口径：发生额、余额、期末值、累计值、平均值、比例值。
- 可聚合性：是否可跨机构、跨账户、跨时间继续聚合。
- 时间口径：业务日期、上报日期、统计日期、账期或入库日期。

如果同名指标多个来源都能回答但结果可能不同，且用户没有明确口径，必须先追问。

## 明细和预聚合冲突

- 明细表适合回答“有哪些、具体记录、按细粒度条件筛选”。
- 预聚合表适合回答“固定口径下的总量、趋势、排名、监管统计”。
- 预聚合表中的比率、均值、占比通常不能再次直接平均。
- 预聚合表中的余额、存量、期末值通常不能跨时间求和。
- 如果用户同时要求预聚合结果没有的筛选维度，应说明当前配置不支持或请求确认是否改用明细口径。

## 日期字段

如果语义配置已经把物理日期字段转换成标准展示格式，应使用转换后的维度口径和筛选值。

如果语义配置没有维护日期格式和转换口径，不能根据列备注或字段名自行假设 `yyyyMMdd`、`yyyy-MM-dd`、时间戳等存储格式。
