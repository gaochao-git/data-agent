# 通用问数策略

## 查询类型

- 明细：明细、详情、列表、逐笔、上报记录、原始记录、查看具体数据。
- 聚合：统计、合计、总量、数量、金额、占比、分布、按某维度汇总。
- 趋势：按日、按月、按季、按年、变化、走势、趋势、时间序列。
- 排行：Top、排名、最高、最低、最多、最少、前 N。
- 对比：同比、环比、较上期、不同机构/区域/产品之间比较。
- 概念解释：问业务概念、字段含义、指标定义，不直接查数。

## 明细与汇总选择

- 用户要明细、列表、详情、逐笔、上报记录时，优先使用明细口径。
- 用户要监管汇总、趋势、排行、报表口径时，优先使用已维护的汇总或预聚合口径。
- 用户指定的筛选字段、展示字段只在明细口径存在时，应回到明细口径。
- 用户指定按月、按季、按年时，优先匹配相同时间粒度的口径；没有对应粒度时，确认是否允许从更细粒度聚合。
- 明细口径和预聚合口径都能回答但结果可能不同，且用户未说明粒度或口径时，必须追问。

## 指标可聚合性

- 金额、笔数、户数、次数通常可加，但必须确认粒度不重复。
- 余额、存量、时点值通常是快照，不能跨时间直接 SUM。
- 比率、占比、率值不能直接 SUM，也不能默认 AVG，除非语义配置维护了明确加权口径。
- 平均值不能二次平均，除非有分子分母或明确加权规则。
- 最大值、最小值只能表达极值，不能代表总量。
- 记录数可以表达明细行数，但不能替代业务对象数量，除非粒度明确。

## 预聚合口径

预聚合表或预计算指标必须看指标说明判断是否还能继续聚合：

- 已按机构加月份聚合的金额，可在同一月份跨机构求和，前提是机构之间不重复。
- 已按月份生成的余额，通常不能跨月份求和；月度趋势应展示每月快照值。
- 已计算好的比率、占比、均值，不能在更高层级直接 AVG，除非配置明确说明加权规则。
- 预聚合表的粒度不满足用户筛选或分组字段时，不能硬查，应换更细粒度口径或追问。

## 时间范围

- 趋势、排行、对比、Top N、分布分析通常需要明确时间范围。
- 用户只说“近期、本期、最近、目前”等模糊时间，不能擅自换成具体日期。
- 总量查询和明细查询可不强制时间范围，但如果全量数据可能误导，应提示用户补充时间范围。

## 同名和多来源冲突

同名指标不能只按名称选择，必须结合：

- 查询类型：明细、汇总、趋势、排行、对比。
- 数据来源：明细、汇总、预聚合、报表口径。
- 粒度：账户、机构、地区、日、月、季、年。
- 指标说明：是否快照、是否可加、是否预计算。
- 用户指定的筛选和分组字段是否被当前口径覆盖。

如果多个口径都可能回答且结果可能不同，必须追问。

## DSL 规划知识

- 明细查询：`metrics=[]`，展示字段放 `dimensions`。
- 聚合查询：`metrics` 放聚合指标，`dimensions` 放分组字段。
- 趋势查询：必须包含时间维度和合适 `time_grain`。
- 排行查询：必须有明确排序指标和 limit。
- 对比查询：优先拆成基础查询，再做确定性计算；不要让模型口算长数字。

这些是业务知识检查项，不替代系统提示词定义的智能问数主工作流，也不替代当前指标集中的真实指标、维度和口径。
