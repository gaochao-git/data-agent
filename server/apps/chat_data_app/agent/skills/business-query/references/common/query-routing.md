# 指标集路由知识

## 使用阶段

本文件只用于未手动选择指标集时，辅助理解用户问题并准备调用指标集选择工具。

路由知识不能直接决定最终指标集，也不能替代当前数据源组中真实存在的指标集。最终是否可查、选哪个指标集，必须由 `select_semantic_config_tool` 在真实指标集摘要中判断。

## 路由目标

调用指标集选择工具前，先明确以下内容：

- 用户问题属于哪个业务领域或业务对象。
- 用户要明细、汇总、趋势、排行、对比还是概念解释。
- 用户更可能需要明细口径、汇总口径、预聚合口径还是监管报表口径。
- 用户是否指定了时间范围、统计粒度、筛选对象或分组维度。
- 是否存在同名指标、多来源、多粒度或多口径冲突。

明确这些内容后，把原始问题和必要的业务限定一起作为 `query` 传给指标集选择工具。不要在 `query` 中编造指标、维度、表名或 SQL。

## 领域识别

### 订单销售分析

出现以下业务词时，通常属于订单销售分析领域：

- 订单、订单明细、订单状态、下单、支付、成交、退款、取消。
- 商品、SKU、SPU、类目、分类、父类目、商品排行。
- 销量、销售额、成交金额、订单数、客单价、购买用户、复购。

如果用户问“销量、销售额、订单数、商品排行、类目分布、成交趋势”，应优先寻找订单销售相关指标集。

### 备付金非现场监管

出现以下业务词时，通常属于备付金非现场监管领域：

- 支付机构、法人机构、分支机构、机构编码、机构名称。
- 备付金、备付金账户、合作银行、账户余额。
- 上报数据、监管报表、非现场监管、统计期、账期。
- 交易、退款、清算、结算、提现、充值、发生额。

如果用户问“机构上报明细、监管汇总、备付金余额、账户余额、按机构统计、月报/季报”，应优先寻找备付金监管相关指标集。

## 明细、汇总和预聚合路由

- 用户要“明细、详情、列表、逐笔、具体记录、上报记录”时，路由时强调明细口径和展示字段。
- 用户要“统计、合计、趋势、排行、Top N、分布、报表”时，路由时强调聚合指标、分组维度和时间粒度。
- 用户提到“监管报表、月报、季报、固定口径、已计算结果”时，优先考虑汇总或预聚合指标集。
- 用户指定的筛选或分组维度只在明细口径可能存在时，不要强行选择缺少该维度的预聚合指标集。
- 明细和预聚合都可能回答但结果可能不同，且用户没有明确口径时，应让选择工具返回候选后请用户确认，不要自行猜。

## 选择工具 query 写法

传给 `select_semantic_config_tool` 的 `query` 应保留用户原问题，并可追加简短业务限定。例如：

- 用户问“查商品销量排行”，可传“查商品销量排行；订单销售分析；聚合排行；需要商品维度和销量指标”。
- 用户问“查看机构上报明细”，可传“查看机构上报明细；备付金非现场监管；明细查询；需要机构和上报记录维度”。
- 用户问“本月备付金余额趋势”，可传“本月备付金余额趋势；备付金非现场监管；趋势查询；需要余额指标和时间维度”。

不要把技能里的常见字段、表名或示例指标当成真实可用项；真实匹配必须由指标集选择工具基于当前指标集摘要完成。

## 路由失败或歧义

- 如果多个指标集都可能完整覆盖，必须让用户选业务口径或指标集。
- 如果用户同时要求多个业务领域或多个指标集才能回答，应提示当前问题需要拆分或选择范围。
- 如果用户问题缺少决定性口径，例如明细还是汇总、上报口径还是预计算口径，应先追问最关键的一点。
- 如果没有任何指标集覆盖，说明当前指标体系不支持，并指出缺少的指标、维度或业务口径。
