# Office 交付质量规则

本文件只保留适用于 ChatData 的质量规则。所有命令必须通过 `officecli_run(command_args=[...])` 调用；每个数组元素是一个独立参数，不使用 shell、`open`、`close`、`watch` 或在线安装命令。

## 通用交付门

交付前按顺序执行：

1. 用 `officecli_run(command_args=["validate", file])` 检查 OpenXML 结构。
2. 用 `officecli_run(command_args=["view", file, "issues"])` 检查空内容、溢出、破损引用、缺失资源和格式问题。
3. 用 `officecli_run(command_args=["view", file, "text"])` 检查占位符、残留转义字符和明显的截断内容。
4. 需要视觉确认时优先 `view screenshot` 截图后用 `file_read` 读图（报 `No headless browser available` 时改用 `view html`）；结构校验通过不等于页面排版正确。
5. 通过检查后，将最终文件放入 `outputs/` 并调用 `present_artifacts`。检查失败时修复后重跑，不声称已交付。

## Word

- 排版口径只有两套：普通报告以标准汇报模版为准（样式映射与验收见 `standard-report.md`），党政机关公文以 `gb-t-9704-2012.md` 为准；不使用这两套之外的通用字体字号默认值。用户提供了模板或明确要求样式时一律按用户执行，口径只约束用户未指定的部分；模版样式优先于任何内联尺寸。
- 非简单文档应有清晰的标题、一级/二级标题和正文层级，不要把全文写成无样式的 Normal 段落。
- 用 `spaceBefore`、`spaceAfter` 和分页属性控制间距，禁止用连续空段撑版面。
- 超过一页的报告应考虑页眉、页脚和动态页码；不要写死“第 1 页”。
- 表格和图表交付前检查是否跨页异常、文字裁切和图片缺少替代文本。

## Excel

- 计算出的 KPI 应使用公式，不要把模型算出的结果硬编码进 KPI 单元格。
- 图表优先引用工作簿内可见的单元格范围；不要依赖隐藏列或隐藏工作表中的公式结果。
- 修改上游公式后，重新写入或读取关键下游公式，确认缓存值没有停留在 0 或旧值。
- 检查 `#REF!`、`#DIV/0!`、`###`、空工作表、空图表系列和列宽不足。
- 数据量较大时，原始数据、汇总数据和展示页分层；展示页应便于用户打开后直接阅读。

## PowerPoint

- 每页只保留一个主要结论，标题和正文建立明显层级；正文不要小到无法投屏阅读。
- 沿统一网格排布内容，保持页边距、列宽、卡片间距和对齐线一致，不用“填满页面”替代信息组织。
- 图表、图片和连接器必须有明确用途；图片应有替代文本，流程连接器应连接正确的对象。
- 交付前检查空页、元素越界、文字裁切、深色背景上的低对比度文字和重复标题。
- `view html` 或静态截图只能验证静态布局；动画、切换和运行时特性需要明确标注未验证。

## 规则边界

- `morph-ppt`、3D 模型、融资路演、学术论文、财务模型和表单是专项场景，只有用户明确提出时才新增独立技能。
- 上游技能中的 `curl`、`bash`、shell 变量、heredoc、常驻进程和 `watch` 示例不适用于 ChatData，不得直接复制。
