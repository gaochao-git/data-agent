# 长报告写作工作流

多章节长报告（经营分析、专题汇报、工作总结、调研报告等）的成稿过程治理。短文档（单节、几段内容）不走本流程，直接按 `SKILL.md` 工作流程执行。本文件只定义过程步骤；样式口径以 `standard-report.md`、`gb-t-9704-2012.md` 为唯一事实源，交付校验命令以 `delivery-quality.md` 为准，均不在此重复定义。

任务书/用户要求是最高依据：本流程整理出的需求、样式、大纲与其冲突时，以任务书/用户要求为准。

## 中间产物约定

- 需求说明、样式清单、大纲、校验记录一律写入 `workspace`，是过程文件不是交付物；只有最终文件进 `outputs`。
- 最终回复只呈现结论性摘要（见第 7 步），不罗列中间文件内容。

## 1. 需求整理

从任务书/用户消息提炼并写入 `workspace/<业务名>-需求说明.md`：报告目标、受众、核心问题、数据来源（对应哪些查询结果或文件）、体裁与篇幅。任务书明确的条目照录，不虚构补充；缺失且影响成稿的关键信息先澄清，无法澄清时在需求说明中记录假设。

## 2. 样式解析

确定本次适用的样式口径，把具体属性值解析成 `workspace/<业务名>-样式清单.md`，作为第 4 步生成与第 6 步视觉校验的对照基准：

- 普通报告：从 `standard-report.md` 样式映射表解析各级字体、字号、行距、页边距、页码格式；
- 党政机关公文：从 `gb-t-9704-2012.md` 解析；
- 用户提供模板：用 `view annotated` 从模板读取实际属性，未覆盖层级按上述默认口径补齐。

样式清单是"解析结果"，不是自由设计。用户提供模板或明确要求样式时一律以用户为准，默认口径只补齐用户未覆盖的层级；逐项记录来源（标准/公文/用户模板），与默认口径冲突时以用户样式为准。

## 3. 结构规划

生成 `workspace/<业务名>-大纲.md`：章节层级、每章要点、数据来源映射（哪一章引用哪份查询结果/文件）。大纲是后续填充与校验的唯一索引；成稿中调整结构先改大纲再改正文，保持索引有效。

## 4. 分块生成

按大纲逐章生成，每次只处理一个模块：写完一章即对照大纲核验（章节号、标题、要点覆盖完整）后锁定，再进入下一章，避免全局漂移。要求：

- 引用数据必须标注来源（查询结果/文件路径），关键数值先用 `calculator_tool` 校验；
- 长章节优先按 `standard-report.md` 执行策略用 `batch` 按章节提交，样式逐项配齐不漏设。

## 5. 内容校验

全稿完成后做对抗性审查，逐章核查三项：数据准确（与来源查询结果一致）、逻辑自洽（结论有数据支撑）、证据可溯源（来源标注可回查）。发现问题回到第 4 步只修正对应模块；校验记录（问题与修复结论）写入 `workspace/<业务名>-校验记录.md`。

## 6. 视觉校验

对照样式清单逐项检查：字体字号、行距、页边距、页眉页脚与页码、图表位置与编号、跨页约束（表格表头跨页重复、标题不悬空）。工具侧检查按 `delivery-quality.md` 通用交付门执行（`validate`、`view issues`、`view text`、`view html`），本流程不重复定义命令。

## 7. 最终交付

按 `SKILL.md` 工作流程第 7-8 条执行：校验通过后 `file_copy` 到 `outputs` 并调用 `present_artifacts`。最终回复呈现：需求要点、成稿结构、关键数据结论、内容与视觉校验结论、遗留假设；需要后续迭代时在需求说明中追加修改记录（日期与变更摘要）。
