# 标准汇报模版格式

本规范是普通报告的默认格式：经营分析、专题汇报、工作总结、情况报告、调研报告等汇报材料一律执行本文件定义的标准汇报模版样式约定。技能附带可执行的 `.docx` 样板，但排版契约以本文件的样式映射为准。它不是党政机关正式公文格式；请示、通知、决定、函等公文汇报应优先使用用户单位模板，并按需参考 `/mnt/skills/officecli/references/gb-t-9704-2012.md`。

## 适用原则

- 用户提供了模板文件或明确要求样式（字体、字号、颜色、行距等）时，一律按用户要求执行；本规范只约束用户未指定的部分。
- 用户未要求时，新建 Word 以 `officecli create` 为起点，按下方样式映射表逐级显式设置样式、字体、字号、对齐和行距——这是按标准配置，不是自由发挥；不得使用表外取值。
- 编辑已有文档时先用 `view annotated` 读取现有样式，匹配文档已有约定；本表用于补齐缺失层级和验收。

## 样式样板

`/mnt/skills/officecli/assets/standard-report-template.docx` 是本标准的可执行样板，已包含：

- 封面、目录、正文三个 section；
- 封面和目录不显示页码，正文 section `pageStart=1`；
- 真实 `Heading 1/2/3` 样式（带 `outlineLvl`），可作为 TOC 源；
- TOC 活域（Word 打开后右键“更新域”生成目录）；
- 标题、副标题、报告信息、正文、表格、图表、表题、图题、说明和页脚页码。

生成前可用 `view annotated`、`outline` 或 `get <路径> --depth` 查看每一级的具体属性配置（字体/字号/行距/缩进/边框），照其落地。样板与本文不一致时以本文为准，并按映射表重新生成样板。

## 执行策略：分场景选择写入方式

**新建报告**：正文段落较多时优先把全文按大纲和样式映射表生成为一个 batch JSON 数组，一次 `batch` 提交整篇（远快于逐段 `add`）；每个元素的 `props` 仍须按样式映射表配齐字体、字号、行距、缩进，不因批量而漏设。段落很少（如只补两三段）或需要边写边看结构时，逐条 `add` 更直接。长报告可按章节拆成多个 batch，单批失败重提成本低。

**编辑已有报告**：先 `view`/`query` 读取结构和目标段落的 `@paraId`，优先用 `/body/p[@paraId=…]` 精准定位后再修改（单条 `set` 或小批量）；`batch` 内 remove/move 会使位置索引动态重算，按删除前快照写 `p[N]` 会错位，含 remove/move 的批量应改用 `@paraId` 定位。

写入后 `view annotated` 核对样式，样式错漏用单条 `set` 点状修正。`batch` 是原子的：一条失败整批不落盘，按逐条 ERROR 修复后整批重提。具体 JSON 结构见 `word.md` 的 batch 章节。

## 页面与版式

- 纸张：A4（21cm × 29.7cm）。
- 页边距：上下 2.54cm、左右 3.17cm；需装订时在左侧预留装订线位置。
- 分节：封面、目录、正文分为独立 section；封面和目录不显示页码，正文另起一页并从 1 开始。
- 页码：位于正文页面底端居中，格式为 `- 1 -`；封面和目录不显示页码。
- 英文与数字：Times New Roman；中文按样式映射表字体执行。
- 段距：段前段后默认 0 行，间距用 `spaceBefore`/`spaceAfter` 属性控制，不用空段落。
- 标题标点：独立成行的标题句末不加标点。

## 样式映射

配置时把下表 pt 值原样写入 officecli `size=`（单位为磅，`size=16` 即 16pt），不得按半磅翻倍。

- `ReportTitle`（报告标题）：主标题；标准为方正小标宋简体 22pt（二号）、居中。
- `ReportSubtitle`（报告副标题）：副标题或主题语；标准为楷体_GB2312 16pt（三号）、居中。
- `ReportMeta`（报告信息）：汇报单位、日期等封面信息；标准为仿宋_GB2312 14pt（四号）、居中。
- `Heading 1`（一级标题）：编号“一、”；黑体 16pt（三号），带 outline level 1。
- `Heading 2`（二级标题）：编号“（一）”；楷体_GB2312 16pt（三号），带 outline level 2。
- `Heading 3`（三级标题）：编号“1.”；仿宋_GB2312 16pt（三号）加粗，带 outline level 3。
- `Normal`（正文）：仿宋_GB2312 16pt（三号）、两端对齐、首行缩进 2 字符、固定 28pt 行距。
- `KeyConclusion`（关键结论）：只用于最重要的 1-3 条结论，不要把大段正文放入强调块；仿宋_GB2312 16pt 加粗、深蓝色 `#1F4E79`，首行缩进 2 字符，段前/段后 6pt。
- `TableCaption`（表题）：表格上方，含表序与表题，如“表1 ×××”，阿拉伯数字全文连续编号、居中；仿宋_GB2312 12pt（小四号）。
- `FigureCaption`（图题）：图表下方，含图序与图题，如“图1 ×××”，阿拉伯数字全文连续编号、居中；仿宋_GB2312 12pt（小四号）。样板内置一张柱状图案例（营业收入/营业成本），图表标题、图例、配色和图题可直接对照复用。
- `Note`（说明文字）：口径、数据来源、注释等次要信息；仿宋_GB2312 12pt（小四号）、灰色 `#595959`，首行缩进 2 字符，固定 20pt 行距。
- `TableHeader`（表头）：仿宋_GB2312 12pt（小四号）加粗、居中。
- `TableText`（表格正文）：仿宋_GB2312 12pt（小四号）、居中。
- 表格版式：全边框黑色细实线；表宽为版心 100%、`jc=center` 居中；跨页时表头行重复；不套用 16pt 正文字号。

标题编号按“一、”“（一）”“1.”序列执行：文档无自动编号时把编号写进标题文本；用户模板带自动编号时不要手写，避免重复。新增段落只写标题文本并设置对应 `Heading 1`、`Heading 2` 或 `Heading 3` 层级样式。样板已内置这些样式；从 `officecli create` 起步时没有内置样式，必须按映射表逐级显式设置属性并写入段落样式名，不能只写字体属性而漏掉大纲级别（否则 TOC 无法识别）。

## 内容组织

- 封面与正文分节：封面不显示页码，正文另起一页并从 `- 1 -` 开始编号；目录作为独立 section 时同样不显示页码。
- 结论先行：管理层摘要应优先写事实、判断、影响和行动，不先堆背景。
- 一段一意：避免超长段落；重要数据保留统计范围、单位和时间口径。
- 层级克制：通常不超过三级标题；层级过深时优先重组内容。
- 表格可读：表头简洁、单位明确；表格字号按样式映射表执行（12pt），不套用 16pt 正文字号。
- 图表克制：白底，以深蓝为主色、红色作重点强调；避免渐变、立体效果和无业务含义的装饰。
- 图表段落必须使用单倍/自动行距，不能继承正文固定 28pt 行距；否则内嵌图表会被行高裁切，出现只显示图例或边框的假象。模版中的图表段已按单倍行距设置。
- 密级、单位标识和页眉内容只有用户明确提供或单位模板已有时才写，不自行推断。

## 字体环境

服务器与渲染环境已安装标准字体：仿宋_GB2312、楷体_GB2312、黑体、宋体、方正小标宋简体、Times New Roman。docx 一律直写标准字体名，不做任何回退替换；不得使用 STFangsong、Kaiti SC、Heiti SC 等替身字体名，避免口径漂移。

注意：`officecli create` 的默认中文是等线、11pt，不在标准内；新建文档后必须按样式映射表逐级显式覆盖字体和字号，**包括分页符、空段在内的每一个段落**（漏设即残留等线；用 batch 一次写入时，在每段元素的 `props` 中同样配齐，不得留默认）。分页优先在标题上设 `pageBreakBefore=true`，少造空段。交付文档里若出现等线，说明 create 默认未被覆盖，按样式映射表修正。

## 交付检查

1. `officecli validate` 必须通过。
2. 用 `view annotated` 逐级核对字体、字号、对齐和行距与样式映射表一致，标题编号没有重复或缺失。
3. 用 `view issues` 检查空段、占位符、裁切、表格越界和图片替代文本；动态 `PAGE` 域在 Word 首次打开前可能没有缓存结果，这不是固定页码，可保留并明确由 Word 打开时更新。
4. 用 `view text` 确认不存在 `{{...}}`、`TBD` 等未替换占位符。
5. 对超过一页、包含表格/图表或需要正式汇报的文档，必须进行 HTML、截图或目标 Office 查看器的视觉检查；结构校验通过不代表排版正确。
6. 表格逐张核对：`get /body/tbl[N] --depth 3` 抽查表头加粗、12pt、全边框黑色细实线和跨页表头重复，与表格标准不一致即修复。
7. 用 `view stats` 核对全文字体/样式分布：只允许出现方正小标宋简体、仿宋_GB2312、楷体_GB2312、黑体、宋体、Times New Roman；出现等线或替身字体名即样式不统一，必须修正。
