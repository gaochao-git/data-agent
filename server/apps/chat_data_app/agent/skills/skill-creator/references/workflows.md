# 技能工作流设计参考

## 顺序工作流

适合步骤明确、顺序不能乱的任务。写法要让模型知道每一步完成后才能进入下一步。

模板：

```markdown
## 工作流程

1. 收集输入：确认用户目标、范围、时间、对象。
2. 读取资料：加载必要参考文档或数据说明。
3. 构建方案：选择指标、维度、处理方式。
4. 执行处理：调用工具或脚本完成确定性步骤。
5. 校验结果：检查字段、格式、空数据、异常值。
6. 输出结果：按固定格式总结并给出产物路径。
```

适用示例：

- 经营分析报告
- 数据质量检查
- 看板生成
- 周期性指标复盘

## 条件工作流

适合根据用户目标分流的任务。

模板：

```markdown
## 场景判断

- 如果用户要趋势分析，走“趋势分析流程”。
- 如果用户要结构占比，走“结构分析流程”。
- 如果用户要异常诊断，走“异常诊断流程”。

## 趋势分析流程

1. ...

## 结构分析流程

1. ...
```

适用示例：

- 销售分析技能
- 客户画像技能
- 风险监控技能

## 校验工作流

适合输出结构化文件、脚本或配置的任务。

模板：

```markdown
## 完成判定

同时满足以下条件才算完成：

1. 已读取必要参考资料。
2. 已生成目标文件。
3. 已执行校验脚本或规则检查。
4. 失败时给出明确原因和可修复项。
```

## 设计原则

- 关键步骤写在 `SKILL.md`。
- 详细业务规则放 `references/`。
- 稳定计算或格式转换写成清晰步骤说明，不放脚本（平台不支持 `scripts/` 目录）。
- 不要把“可能用到”的所有知识都塞进正文。
