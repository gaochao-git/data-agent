## 4. 缺陷 DEF-2026-11-15-01：新任务压缩卡仍全堆末尾（回归）

**现象**：21:18 跑的「语义文件读取10遍统计」任务（3 次压缩，修复后产生），`GET /api/chatdata/conversations/{cid}/subagent-tasks/{tid}` 返回 `result_meta.subagent_trail` 共 67 条，3 张压缩卡下标 **[64, 65, 66]** 连续堆末尾；浏览器过程视图里三张卡 y 坐标 -1296 / -1260 / -1224，正文被挤到后面。与用户此前截图一致。

**根因**：上一轮加的「防堆叠兜底」拿绝对下标做判断 `if index <= previous + 1: index = min(previous + 2, len(merged))`。真实场景里压缩记录顺序与锚点位置并不单调（第一次压缩的锚点已被后续压缩删掉 → 落末尾 64，第二、三次锚点分别在 26 / 49），于是 **26、49 被误判成「堆叠」强行推到末尾**，加上 `min(..., len(merged))` 截断，三张卡全部叠在 [64,65,66]。用真实数据离线复现旧逻辑，输出与持久化完全一致。

**为什么单测没抓到**：既有用例只覆盖「锚点分散 t2/t4/t6」与「锚点全部重复 t2」，没有覆盖「部分锚点失效 + 其余锚点在早期」这一真实形态。

**修复**：`subagent_trail.py` 用 `_trail_anchor_index`（找不到返回 -1）替代 `_trail_insert_index`；新增 `_compaction_targets` 按**目标位置升序**排列压缩卡，锚点失效时借用它之后最早的已知位置以保持发生顺序、全部失效时均匀铺在过程尾部；插入时按 `target + 已插入卡数` 补偿偏移，仅当**目标位置相同**才做防堆叠。新增两条回归用例（部分锚点失效、全部锚点失效）。

**修复验证**：用同一份真实数据重算 → 压缩卡下标 **[26, 28, 51]**，相邻间隔 `[2, 23]`，id 顺序 `c1/c2/c3` 保持；既有 `[4,9,14]` 与重复锚点用例断言不变。

> 存量已持久化的 trail 按用户 21:14 拍板**不做兼容/迁移**；本次修复只影响之后新跑的任务。

## 7. 续修：任务卡「正在压缩」（22:3x~22:5x）

**问题**：review 第 2 点属实但此前按产品增强暂缓。运行中任务卡的进度条只显示「正在使用 XX 工具」，真摘要压缩（实测 19s）期间用户看不到任何压缩状态；过程视图的占位卡又只在会话消息流里，工作台页面看不到。

**实现**（`subagent_stream.py` / `subagent_task_service.py` / `types/index.ts` / `SubagentTaskRow.vue`）：

1. `_SubagentStreamState.compressing`：有效 started 帧到达时置 `True`，completed 记录转发时置 `False`；无效 started（无 id）不置位。状态标记放在转发函数内部，避免主分发函数 `_process_subagent_chunk` 认知复杂度超 15。
2. `_subagent_progress_snapshot` 输出 `compressing`，随既有 5s 心跳落 `progress` 并经 `subagent_task_updated` SSE 推给前端；**百毫秒级「跳过摘要」压缩不会被 5s 采样捕获**，因此不会闪烁，只有长摘要压缩才显示。
3. `SubagentTaskRecord.progress` 在终态剥掉 `compressing`：异常中断收不到 completed 时，历史详情/工具输出不会残留永不结束的「正在压缩」。
4. 前端 `SubagentTaskProgress` 加 `compressing` / `compaction_count` 两个字段（后者此前只在后端返回、类型缺失，type-check 抓到），`progressText` 在 `compressing` 时优先显示「正在压缩上下文，整理已用信息」。

**验证**：后端扩大定向 **244 passed**（新增 3 例：started/completed 窗口、无效 started 不置位、终态剥标记）；前端 type-check 通过 + 定向 **33 passed**（新增 2 例：压缩中文案、完成后回落到工具文案）；ruff check / ruff format（顺带修复 HEAD 遗留的 4 个文件格式漂移）/ 认知复杂度 0 超标 / `sse_vocabulary` / `git diff --check` 全绿。
