### 场景1 多曲线——发现的可用性问题（非崩溃，建议关注）

真点生成的双曲线图里，订单总额（13.7万~54.6万）与订单总数（74~226）**量级差约 2000 倍**，共用单一 Y 轴（Y 标签「数值」），导致低量级的「订单总数」蓝线被压成贴着 0 的水平直线，肉眼完全看不出波动。

后果：模型回答称「蓝色线相对平稳、范围74-226、峰值226」，但图上蓝线视觉上不可辨——这些数值实际来自同轮查询结果表格，不是从图上读出的数据。这与 data2image「用图代替行数据进上下文」的设计初衷存在张力：多指标量级差异大时，弱势曲线失去可视化价值。

代码根因：`chart_render.py::_render_group_png` 用单一 `axis`、无双 Y 轴、无量级归一化（所有曲线共用 `axis.plot` + 同一 Y 刻度）；`MAX_LINES_PER_CHART=5` 允许多曲线但未处理量级差。这是设计取舍而非 bug——单曲线、量级相近的多曲线均正常。若要支持量级差异大的多指标，可考虑：双 Y 轴 / 每条曲线独立归一化后标注实际值 / 提示模型量级差大时拆图。属后续增强，不在本轮修复范围。

### 场景4 前端图片可见性的设计边界（已澄清）

data2image 生成的 PNG **不内嵌到对话消息流**（DOM 无 `<img>` 标签），工具卡只显示文本回执（意图+耗时，如「数据转折线图 / 将查询结果绘制成折线图 / 134ms」）。这与 `read_image` 分工一致——转图不塞 base64、避免 checkpoint 膨胀。图片通过 `GET /conversations/<id>/workspace-files` 暴露（实测返回 `outputs/2024年1月每日订单量_112504234.png`，49258B），用户在文件面板 outputs 目录查看/下载，符合「.system 与 outputs 用户可见可下载」的产品口径。上一轮标注的「前端缩略图展示未确认」至此澄清：并非缺陷，是设计上就不在消息流预览。

新增的 data2image 工具**真浏览器多场景验证通过**：单曲线、双曲线、日粒度三种图表均正确渲染中文、落盘 outputs、read_image 读图驱动模型做出与图吻合的分析；失败边界（字段不存在、自建文件）均正确拒绝且无违规产图；图片在文件面板 outputs 可见可下载。后端单测 210 passed、错误探针全程 0。
