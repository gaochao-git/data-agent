## 关键发现（产品行为，非工具 bug）

1. **数据量决定工具选择**：小数据量题（Q2 5条、Q4 28条）模型正常走 data2image+read_image；大数据量题（Q1 939条、Q5 336条）模型倾向把整份行数据读进上下文逐行推算（`读取文件`/`读取剩余数据`/`精确计算`），Q1 甚至触发上下文压缩后才转图——**绕开了 data2image「用图代替行数据」的设计初衷**。
2. **长周期回答易循环**：Q1（14min）、Q5（7min未收敛）、Q8（6min后段）在长周期/多区间场景出现"反复重述分析、每次结论略不同"的循环，步数停滞或空转；Q1/Q5 截图留证。工具链本身正确（SQL+转图+读图都成功），是模型层在超长上下文下的行为问题。
3. **图像优先可生效**：Q8 明确"基于这张趋势图，我判断3个区间…下面用SQL逐条验证"，且验证①数值吻合——read_image 视觉注入 + 图先于明细的策略真实可用。
4. **极限值是 SQL 核实而非纯读图**：Q2 的"最高5天/最低5天"精确数值来自 SQL 查询，图用于展示；题目"先图定位再SQL核实"的顺序被模型实现为"先SQL核实后图展示"，结果一致但顺序相反。
5. **5 线边界**：Q9 因题目为假设语气，模型未实际查渠道字段/未画图，只给了限制说明+拆分方案；未真正触发 `_MAX_Y_FIELDS=5` 的运行时拒绝。
