# ChatData 浏览器点击测试基线

> 本文档是 ChatData 发布前和回归测试的浏览器执行基线。每条用例都必须通过页面操作完成，并记录页面结果、关键请求路径和最终状态。
>
> 这不是 API 单元测试清单。后端接口、数据库、LLM 和执行器的纯接口契约仍由 `tests/api/` 与 `tests/unit/` 覆盖；本基线只验证用户从页面能完成的功能，以及页面是否调用了正确的权限入口。

### 1.4 测试用例的分解方式

每个模块按以下顺序设计用例，避免只测“主流程成功”：

1. **进入与可见性**：页面能否打开，角色能看到哪些资源和操作。
2. **配置与持久化**：新建、编辑、保存、取消、删除，刷新后是否一致。
3. **核心执行**：模块的主要业务动作是否完成，输入、输出和状态是否正确。
4. **跨模块联动**：上游配置是否能被查询、看板、历史、文件或 Agent 正确消费。
5. **权限与数据隔离**：普通、管理员、不同用户、无权限和权限回收场景。
6. **异步与失败恢复**：loading、重复点击、取消、超时、断流、部分成功和重试。

后续用例中的“前置、操作、预期、边界、关联”分别对应上述分解，编号前缀对应本节模块目录。新增页面功能时，必须先补本节功能范围和覆盖矩阵，再新增详细用例。

## 2. 测试规则

### 2.1 测试角色

| 角色 | 说明 |
| --- | --- |
| `SYS_ADMIN` | 系统管理员，具备后台管理权限和数据源管理白名单权限 |
| `USER_A` | 普通用户，有指定机构和数据源执行对象权限，可创建私有语义模型、看板和技能 |
| `USER_B` | 另一个普通用户，用于验证私有资源隔离和公共资源只读 |
| `NO_SCOPE_USER` | 无可用机构或执行对象权限的普通用户 |
| `REVOKED_USER` | 测试过程中被回收部分机构或执行对象权限的用户 |

若部署环境将角色授权放在上层 BFF/controller，仍必须从浏览器分别验证 UI 显示、请求路径和服务端返回；不能只以按钮隐藏作为权限验证。

### 2.2 前置数据

- 至少准备一个 MySQL 数据源组、一个 Hive direct 数据源组和一个 Hive HTTP 数据源组；无法连接某类真实数据源时，使用测试环境的可控 mock，但仍保留该页面流程。
- 至少准备一个多成员数据源组，并为成员设置不同的 `member_name`、权限和可观察的成功/失败结果。
- 表结构至少包含：主键、唯一键、普通索引、时间列、数值列、枚举/状态列、无备注列、含中文备注的表和字段、可自关联的层级表。
- 准备一个系统公共语义模型、一个普通用户公共模型、一个 `USER_A` 私有模型、一个 `USER_B` 私有模型；准备一个尚未复核的基础模型，初始为禁用。
- 准备历史学习记录、评测用例、成功/失败/取消的 SQL 历史、收藏 SQL、个人看板、公共看板和未发布技能草稿。
- 准备文本、Markdown、CSV、TSV、JSON、DOCX、PPTX、XLSX、PDF、空文件、损坏文件和不支持格式的测试文件。
- 准备小查询结果、大于页面展示上限的查询结果、总行数可统计和总行数不可统计的文件。
- 准备可写的测试数据源、不可写或故意失败的数据源，以及可模拟网络超时、权限失败和保存失败的测试开关。

### 2.3 统一验收规则

- 页面打开、切换、关闭、刷新后无白屏、无限 loading、明显布局溢出或未处理异常。
- 保存、同步、执行、停止、删除、发布等操作只产生一次请求；按钮在请求期间不可重复提交，完成后状态与列表一致。
- 仅允许系统管理员操作系统级资源。普通用户的私有资源由 `user_id/owner` 隔离，公共资源可查看但不能修改原件。
- 字段字典的普通用户查看必须走 `/datasources/...` 普通 GET 接口；修改、AI 生成、枚举维护必须只在系统管理页面走 `/admin/datasources/...` 管理接口。不能以 admin 接口作为普通用户查看接口。
- 查询结果统一按 `results[]` 展示；每个成员核对 `member_datasource_id`、`member_name`、`success`、`status`、`sql`、`columns`、`data`、`total_count`、`execution_time_ms`、`error`。
- 查询结果写入 `outputs/query_result` 后，页面展示摘要和结果路径；智能体要回答具体数值、比较、分析或判断空结果时，必须继续从 `result_path` 读取文件，不能把“模型未直接看到结果”当成查询失败。
- 查询执行成功与结果交付成功分开核对。保存失败时检查 `query_status=succeeded`、`delivery_status=persistence_failed`，小结果按约定有限内联，大结果明确提示结果保存失败，不能伪装为普通截断或无条件重跑查询。
- 任何权限失败、数据源不存在、网络失败、模型失败和工具失败都要有用户可读提示；除 SQL 运行接口外，不向前端直接展示后端堆栈。
- 每条用例执行后记录：`PASS/FAIL`、角色、环境、时间、页面截图或录屏、关键请求、实际结果和缺陷编号。

| 管理端 | 后台管理入口、数据源、公共语义模型、评估、全局 SQL 历史、系统配置 | `SYS_ADMIN` | `ENT-02/03`、`DS-*`、`SEM-01/03/04/05`、`EVAL-*`、`GH-*`、`SYS-*`、管理页面上的 `ST-*` |
| 业务端 | 查询入口、私有语义模型、数据智能体（含会话、上下文与技能）、文件/Office、SQL、Builder、看板、收藏 | `USER_A`、`USER_B`、`NO_SCOPE_USER`、`REVOKED_USER` | `ENT-01/03/04`、`SEM-02/06-15`、`AG-*`、`FILE-*`、`CTX-*`、`SQL-*`、`BI-*`、`DB-*`、`FAV-*`、`SKILL-*`、业务页面上的 `ST-*` |

## 4. 详细功能用例

### 4.1 页面入口与权限

#### ENT-01 页面模式切换

- 角色：`USER_A`
- 前置：拥有可用数据源和执行对象。
- 操作：打开 ChatData，依次切换数据智能体、可视化查询、SQL 查询、数据看板；切换数据源、语义模型和执行对象。
- 预期：四个模式都能加载；模式、数据源、语义模型、执行对象状态互不串台；切换后不会重复提交上一个模式的查询。
- 边界：数据源为空时显示空状态，不自动执行查询；刷新后仍进入配置的默认模式。
- 关联：`web-vue/src/views/chat-data/pages/index.vue`；`GET /models`、`GET /config`、`GET /datasources`。

#### ENT-02 管理入口可见性

- 角色：`SYS_ADMIN`、`USER_A`、`NO_SCOPE_USER`
- 前置：分别登录三种账号。
- 操作：打开页面并查看后台管理、数据源管理、全局 SQL 历史、系统语义模型入口。
- 预期：管理员可打开后台管理；普通用户和无权限用户不显示或不可操作管理入口；普通用户仍可进入自己的查询、私有模型和个人看板。
- 边界：仅隐藏按钮不算通过，需确认直接调用 admin 地址返回无权限；普通查看接口不能误走 admin 地址。
- 关联：`ChatDataAdminManager.vue`；`/admin/**` 路由。

#### ENT-03 无权限与权限回收

- 角色：`NO_SCOPE_USER`、`REVOKED_USER`
- 前置：无权限账号或先回收一个执行对象/机构权限。
- 操作：刷新页面，打开历史会话、SQL 历史、看板和语义模型，尝试重新执行已有查询。
- 预期：无权限对象不可选择；历史数据可以按权限显示，但不能绕过当前权限再次执行；页面展示空态或无权限提示。
- 边界：并发请求返回无权限时不出现白屏，不把旧的可执行状态保留为可用。

#### ENT-04 页面状态恢复

- 角色：`USER_A`
- 前置：在四个模式分别配置筛选条件、文件选择和右侧面板状态。
- 操作：切换模式、关闭再打开右侧控制台、刷新浏览器、切换历史会话。
- 预期：允许恢复的会话消息、工具调用、查询结果、文件树和预览状态恢复；新会话不继承旧会话的查询和文件选择。

### 4.2 数据源管理

> 管理页面对应 `datasource_admin.py`；普通查询页面只读数据源和字段字典对应 `datasource_public.py`。本节所有管理用例均需同时核对权限和请求路径。

#### DS-01 数据源列表与空态

- 角色：`SYS_ADMIN`、`USER_A`、`NO_SCOPE_USER`
- 前置：准备有数据源、无数据源和无机构权限三种环境。
- 操作：打开数据源管理或查询页面的数据源选择器。
- 预期：管理员列表显示数据源组及成员；普通用户只显示有权限的数据源和执行对象；无权限用户显示空态或权限提示，不显示其他用户对象。

#### DS-02 新建数据源组

- 角色：`SYS_ADMIN`
- 前置：进入后台管理的数据源页。
- 操作：点击“新建”，填写组名、描述、业务补充和推荐问题，保存；分别尝试空名称、超长名称、重复名称和非法连接信息。
- 预期：合法配置创建成功并出现在列表；必填校验、长度校验和重复校验清晰；取消关闭不产生数据源。
- 边界：保存失败保留表单内容，不生成半成品列表项，不重复请求。
- 关联：`DataSourceManager.vue`；`POST /admin/datasources/groups`。

#### DS-03 数据源类型与执行方式

- 角色：`SYS_ADMIN`
- 前置：打开新建或编辑数据源组。
- 操作：切换 MySQL/Hive；切换 Hive direct/HTTP；配置模板数据源、多成员数据源、机构名称和机构编码；分别保存。
- 预期：表单字段随类型正确切换；配置保存后重新打开值不变；成员名称和成员 ID 在查询结果中保持稳定；direct 与 HTTP 请求使用各自执行器。
- 边界：类型切换不会残留不适用字段；缺失成员凭据、机构编码或连接信息时阻止保存并给出原因。

#### DS-04 编辑配置与取消

- 角色：`SYS_ADMIN`
- 前置：存在已保存数据源。
- 操作：只改基础配置后保存；再次修改后取消或关闭；重新打开数据源组。
- 预期：基础信息保存成功且不触发表结构刷新；取消后恢复服务端值；保存按钮只在有变更时可用。

#### DS-05 拉取表信息与同步元数据

- 角色：`SYS_ADMIN`
- 前置：数据源连接可用，且存在数据库表。
- 操作：点击“拉取表信息”，搜索表名，选择/取消选择表；点击“同步元数据”并刷新列表。
- 预期：拉取只更新当前选择候选，不写入表结构缓存；同步才更新表、字段、备注、主键、唯一键、索引等元数据；按钮 loading 期间不可重复点击。
- 边界：连接失败、空表列表、部分表失败时提示明确，原有配置不被清空。

#### DS-06 模块映射

- 角色：`SYS_ADMIN`
- 前置：存在数据源组。
- 操作：打开“模块映射”，新增、删除模块名，保存；再次打开后取消修改。
- 预期：合法模块保存成功，映射后的入口可加载该数据源；删除映射后对应入口不再展示；取消不改变服务端值；重复模块和空模块被阻止。

#### DS-07 表分组和表选择

- 角色：`SYS_ADMIN`
- 前置：数据源有多张表。
- 操作：新建表分组、重命名、删除；搜索表；选择表、全选、取消全选；保存后刷新。
- 预期：分组名称和表成员正确持久化；删除/重命名有确认或可读错误；筛选状态下全选只作用于当前筛选结果；刷新后状态不丢失。

#### DS-08 表业务说明

- 角色：`SYS_ADMIN`
- 前置：存在已同步的表。
- 操作：编辑表业务说明，保存；再次编辑后取消；在语义模型和问数中确认说明可见。
- 预期：业务说明与原始表备注分开保存；取消不保存；保存后能被语义模型展示和查询上下文使用。

#### DS-09 字段字典查看权限

- 角色：`USER_A`、`SYS_ADMIN`、`USER_B`
- 前置：公共数据源存在已维护和未维护字段字典。
- 操作：普通用户在自己的语义模型中选择字段并点击查看；管理员在系统数据源管理中打开同一字段字典。
- 预期：普通用户只能查看字段字典、枚举、单位和存储格式；普通页面调用 `/datasources/{id}/tables/.../dict` 或 `column-dicts`；管理员页面调用 `/admin/datasources/...`；普通用户不显示 AI 生成、新增、删除、保存入口；`USER_B` 不能看到 `USER_A` 私有字典。
- 边界：未维护字典显示空状态；无权限数据源不能通过改 URL 查看。

#### DS-10 字段字典维护与 AI 生成

- 角色：`SYS_ADMIN`
- 前置：管理员进入系统数据源管理，准备有无备注字段。
- 操作：手工编辑字段描述、逻辑类型、枚举、格式、单位；新增/删除枚举行；对无备注字段点击 AI 生成；保存后重新打开。
- 预期：字段字典保存和回显正确；AI 生成只是填充编辑表单，必须人工确认后保存；取消不保存；生成失败保留原值并给出提示；不修改物理表备注。

#### DS-11 表索引查看与维护

- 角色：`SYS_ADMIN`
- 前置：表包含主键、唯一键和普通索引。
- 操作：打开索引弹窗，查看索引类型、名称和列；新增/编辑/删除索引，保存；刷新后再次查看。
- 预期：主键、唯一键、普通索引展示准确；索引名称、列名和类型校验清晰；保存后持久化；取消不改变原值；数据库执行失败时显示失败，不伪装成功。
- 关联：`TableIndexDialog.vue`；`GET/PUT /admin/datasources/{id}/tables/{table}/indexes`。

#### DS-12 健康检查

- 角色：`SYS_ADMIN`
- 前置：准备连接正常、连接失败和部分成员失败的数据源。
- 操作：点击“校验语义模型/健康检查”，查看成员状态和详情。
- 预期：正常、失败、部分成功状态可区分；结果包含可读错误和检查时间；检查期间不能重复发起。

#### DS-13 默认数据源

- 角色：`SYS_ADMIN`
- 前置：至少两个数据源组。
- 操作：设置一个默认数据源，再取消默认，刷新查询页面。
- 预期：默认标识唯一且持久化；取消后页面不偷偷选旧默认；普通用户的可用范围仍受权限过滤。

#### DS-14 删除数据源组

- 角色：`SYS_ADMIN`
- 前置：存在未被删除的数据源组。
- 操作：点击删除，分别取消和确认；对有关联模型/看板的数据源执行删除。
- 预期：取消不改变列表；确认有 loading，成功后数据源、执行对象和可选项消失；有关联资源时展示明确影响或阻止原因；失败不从页面假删。

#### DS-15 管理权限边界

- 角色：`USER_A`、`NO_SCOPE_USER`
- 前置：账号无管理员白名单。
- 操作：直接访问后台管理入口并尝试新建、修改、字典保存、索引保存、删除。
- 预期：入口隐藏或打开即提示无权限；所有 admin 写接口拒绝；普通用户仍可使用普通数据源和字典查看接口。

### 4.3 语义模型配置

#### SEM-01 模型列表与作用域

- 角色：`SYS_ADMIN`、`USER_A`、`USER_B`
- 前置：准备系统公共、用户公共、两份私有模型。
- 操作：分别打开系统管理和普通用户语义模型入口，切换模型列表。
- 预期：管理员可管理系统公共模型；普通用户可查看可用公共模型和自己的私有模型；`USER_A` 看不到或不能修改 `USER_B` 私有模型；模型来源、维护人和启用状态清晰。
- 边界：没有模型时显示空态，不自动创建。

#### SEM-02 创建私有模型

- 角色：`USER_A`
- 前置：普通用户有可用数据源。
- 操作：点击新建语义模型，填写名称、描述，保存；尝试空名称、重复名称、超长名称和非法字段。
- 预期：只创建 `USER_A` 私有模型；校验失败不保存；新模型可在本人查询入口选择，不能被 `USER_B` 选择。
- 关联：`POST /datasources/{id}/semantic-configs`。

#### SEM-03 创建和编辑公共模型

- 角色：`SYS_ADMIN`
- 前置：进入管理员模型管理。
- 操作：新建公共模型，填写名称、描述、查询规则、推荐问题，保存；编辑后保存、取消。
- 预期：公共模型可被授权用户查询和 Builder 选择；普通用户不能修改公共模型；取消恢复服务端值；重复保存不产生版本或重复记录。

#### SEM-04 一键生成基础单表模型

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：数据源中有尚未建模的物理表。
- 操作：管理员点击“生成基础模型”，选择单表或批量生成；普通用户尝试相同操作。
- 预期：只有管理员可以调用生成接口；每张表生成一个基础模型；生成模型默认禁用，标记待人工复核；表字段、主键、唯一键、物理类型和表列关系正确；字段备注为空时不阻塞生成，后续可人工补充；已存在模型不重复生成。
- 边界：无新表、部分表失败、重复点击、连接失败均有明确结果；普通用户不显示或不能操作该按钮。
- 关联：`POST /admin/datasources/{id}/semantic-configs/generate-basic`。

#### SEM-05 启用、禁用和默认状态

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：存在禁用基础模型和启用模型。
- 操作：管理员复核后启用、再次禁用；普通用户尝试改变公共模型状态。
- 预期：禁用模型不进入智能体或 Builder 可选列表；启用后可选择；普通用户不能改变公共模型状态；保存失败时页面状态回滚。

#### SEM-06 表范围和别名

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：模型包含多张关联表和层级表。
- 操作：选择表、移除表、全量查看表；拖拽调整表顺序或画布布局；设置表别名；切换表名/备注显示；点击表预览。
- 预期：范围、别名、拖拽布局和展示方式正确保存；移除表同步清理相关字段/关系或提示待处理项；表预览显示正确表和有限行数，不修改模型。

#### SEM-07 字段角色和物理信息

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：表有物理字段、主键、唯一键、无备注列。
- 操作：切换字段物理详情；添加/删除维度字段；添加/删除指标字段；编辑显示名称、业务含义和字段备注。
- 预期：字段角色正确；物理列名、表名和物理类型可追溯；无备注字段允许保存空业务备注；字段缺失或物理列不存在时明确标记，不生成不可执行配置。

#### SEM-08 表达式和自由 SQL

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在维度和指标字段。
- 操作：打开表达式编辑器，修改表达式并保存；取消修改；为自由 SQL 指标填写 `rightExpression`；再次执行查询。
- 预期：表达式只在点击保存后更新；取消不影响主配置；`rightExpression` 能在 DSL/SQL 查询中保留并按语义内核编译；原生只读 SQL 仍按 SQL 模式处理，不把表达式误当物理字段。

#### SEM-09 指标聚合扩展

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在数值字段。
- 操作：打开“扩展聚合指标”，添加聚合方式、名称和表达式，保存/取消；在 Builder 中选择新指标。
- 预期：聚合配置保存并能生成 SQL；非法聚合、空表达式和重复名称被阻止；取消不改变指标列表。

#### SEM-10 表关系与自关联

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在主子表和层级自关联表。
- 操作：新增关系，设置左表/列、右表/列、连接类型和条件；配置同一张表的自关联；配置多字段关联；编辑、删除、取消、保存。
- 预期：普通关系、自关联和多字段关联均可保存；关系删除后不残留旧节点；DSL 和 Builder 编译出的 SQL 使用保存后的关系，多字段关联条件完整进入编译结果；非法列、循环或重复关系有明确校验。

#### SEM-11 Ontology 规则

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：模型已保存。
- 操作：打开 ontology 规则，新增、编辑、删除规则，保存和取消。
- 预期：规则回显、保存和取消行为正确；规则进入模型查询上下文；非法 JSON/空规则不导致页面白屏。

#### SEM-12 自动预填候选

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：模型选中多张表，准备有备注和无备注字段。
- 操作：打开自动预填，填写或不填写业务补充，执行；修改候选字段、角色、名称和表达式后取消，再次执行。
- 预期：预填只生成页面候选，不直接保存模型；所有物理字段都可作为基础维度候选；有备注时能作为显示名称参考，无备注时保留合理物理名称；异步返回不会覆盖用户已经修改的内容；失败可重试且不改已保存配置。

#### SEM-13 字段字典只读

- 角色：`USER_A`、`SYS_ADMIN`
- 前置：公共数据源字段字典已维护。
- 操作：普通用户在语义模型字段行点击字段字典；管理员在数据源管理点击编辑字段字典。
- 预期：普通用户只能查看，不能修改数据字典；普通查看使用非 admin GET；系统管理员才有编辑、AI 生成、枚举和保存能力；两处显示内容一致。

#### SEM-14 历史学习

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在属于当前模型的历史查询。
- 操作：打开历史学习，查看候选、应用候选、取消；无历史数据时打开入口。
- 预期：候选来源可追溯；应用只修改当前未保存编辑态，点击模型保存后才持久化；无历史显示空态；权限不允许读取其他用户会话。

#### SEM-15 保存校验、切换和删除

- 角色：模型所有者、`SYS_ADMIN`、`USER_B`
- 前置：准备未保存变更、缺失物理字段、重复名称、有关联看板的模型。
- 操作：保存合法/非法配置；切换模型；删除模型并分别取消/确认。
- 预期：校验覆盖名称、表、字段、表达式、关系和权限；存在未保存变更时切换/关闭有提示；删除成功后不能被查询入口选择；有关联资源时提示影响或阻止删除；非所有者不能编辑/删除。

### 4.4 语义评估

#### AG-05 空结果和查询错误

- 角色：`USER_A`

- 预期：空结果明确显示 0 行；执行失败显示对应成员错误；智能体不能把空结果说成查询失败，也不能把失败说成空结果；页面不重复展示矛盾状态。

#### AG-06 结果落盘和后续分析

- 角色：`USER_A`
- 前置：查询结果会保存到 `outputs/query_result`。
- 操作：先请求“查询/列出结果”，再追问“是多少/比较/分析/计算”；查看结果路径和后续工具调用。
- 预期：首轮可只展示摘要和 `result_path`；后续需要具体数值、结论、比较、分析、计算或判断空结果时，智能体先用 `file_read` 读取结果文件，再回答；不因未内联全部数据而误报查询失败。

#### AG-07 大结果、行数和分段读取

- 角色：`USER_A`
- 前置：准备超过 `CHATDATA_ROW_LIMIT` 的查询结果和超大文件。

- 预期：大结果不会被模型一次性全部注入；超出阈值的工具结果卸载到 `outputs/.tool-offload`，不直接进入上下文，需要时可按路径回读；模型可根据总行数选择统计、聚合或分段读取；行数未知时显示 `unknown` 并允许继续读取；读取范围和返回行数准确。

- 操作：执行查询并观察工具结果、前端结果面板和最终消息。
- 预期：小结果返回有限内联数据并标记 `content_in_context=true`、`result_persisted=false`；大结果明确显示“查询执行成功，但结果保存失败”；同时存在 `query_status=succeeded`、`delivery_status=persistence_failed`；不自动重复查询。

#### AG-09 工具卡片和右侧控制台

- 预期：工具名、参数、结果摘要和顺序真实可读；主结果只展示一次；右侧控制台作为详情，不遮挡主结果；大 JSON 可滚动；历史回放与实时顺序一致。

- 预期：停止后状态为已停止/失败/部分成功之一且前后一致；不残留“生成中”；刷新可恢复已落库消息和结果；未完成任务不会显示为已成功。

### 4.8 统一查询执行与结果交付

> `RUN-*` 不是新的用户页面，而是智能体、SQL 查询、Builder 和看板共同依赖的执行层。这里的用例必须至少从两个不同入口重复验证，确保共享能力没有被某个入口单独改出另一套口径。

#### RUN-01 查询任务生命周期

- 角色：`USER_A`
- 前置：准备智能体、SQL、Builder 和看板各一条可执行查询。
- 操作：分别从四个入口发起查询，观察等待、执行、成功、失败、部分成功、取消和超时状态。
- 预期：所有入口使用统一任务状态和终态语义；状态变化不会跳过必要阶段或长时间停留 loading；刷新后能恢复已持久化状态；预览操作不创建执行任务。
- 边界：重复点击只创建一个任务；任务创建失败不显示为执行中；取消失败有明确提示。

#### RUN-02 多成员结果协议

- 角色：`USER_A`
- 前置：准备单成员、全成功多成员、部分成功多成员和全失败多成员数据源。
- 操作：从 SQL、Builder 和智能体分别执行同一查询，比较结果面板、工具结果和历史记录。
- 预期：均以 `results[]` 表达成员结果；每个成员的 `member_datasource_id`、`member_name`、`success`、`status`、`sql`、`columns`、`data`、`total_count`、`execution_time_ms`、`error` 字段语义一致；成功成员数据不因其他成员失败而丢失。
- 边界：成员名称相同但 ID 不同、成员部分失败和空结果均能区分；前端不重复展示外层结果和成员结果。

#### RUN-03 全局行数限制

- 角色：`USER_A`
- 前置：配置 `CHATDATA_ROW_LIMIT=10000`，准备无 limit、较小 limit、超过上限和带 offset 的 SQL/DSL/Builder 查询。
- 操作：从 SQL、Builder 和智能体分别提交查询，查看实际 SQL、结果行数和结果文件。
- 预期：所有入口采用同一全局上限；用户声明的 limit 不能绕过上限；结果摘要、`total_count`、实际返回数据和文件内容相互一致；offset 不改变上限口径。
- 边界：非法 limit、负 offset、极大整数和空值均被校验；不能因为某个页面参数名不同而绕过公共限制。

#### RUN-04 结果落盘与后续消费

- 角色：`USER_A`
- 前置：准备小结果和大结果，workspace backend 可写。
- 操作：从智能体、SQL、Builder 和看板分别执行；查看结果摘要、`result_path`、文件树、历史结果和看板面板；对智能体结果继续请求数值分析。
- 预期：查询结果统一落到 `outputs/query_result`；页面展示摘要和路径，后续工具可按路径读取；智能体在需要具体结论时先读取结果文件；历史和看板消费的字段、成员、SQL 与原查询一致；内部目录不误作为普通产物。

#### RUN-05 结果保存失败交付

- 角色：`USER_A`
- 前置：模拟 workspace backend 保存失败，分别准备小结果和大结果。
- 操作：从至少两个查询入口执行并观察工具结果、结果面板、历史和看板。
- 预期：小结果按有限内联策略返回并标记 `content_in_context=true`、`result_persisted=false`；大结果显示“查询执行成功，但结果保存失败”；同时有 `query_status=succeeded`、`delivery_status=persistence_failed`；前端不显示普通查询成功，不无条件重跑数据库查询。
- 边界：保存恢复后下一次查询可正常落盘；失败的旧结果不会被错误复用为新查询结果。

#### RUN-06 取消、刷新和结果一致性

- 角色：`USER_A`
- 前置：准备可控耗时的 SQL、Builder 和看板查询。
- 操作：执行中取消并刷新；在任务终态后刷新、切换历史会话或重新打开看板。
- 预期：取消后的任务、历史、结果面板和看板状态一致；旧响应不能覆盖新任务；刷新不产生重复执行；已成功结果可回放，未完成结果不会伪装成功。

#### SKILL-06 工作区导入和运行期加载

- 角色：`USER_A`
- 前置：workspace 中准备合规和不合规技能目录。
- 操作：导入技能；处理缺失 `SKILL.md`、非法目录和重复名称；在对话中使用已发布、草稿和他人不可见技能。
- 预期：合规目录导入为私有草稿；失败明确且不留下半成品；运行期只加载会话技能快照中的已发布技能；管理域文件不直接暴露给 Agent。

### 4.15 系统配置和管理入口

#### SYS-01 模型和系统配置

- 角色：`USER_A`、`SYS_ADMIN`
- 前置：模型配置接口可用和失败各一份。
- 操作：打开模型选择，切换模型和思考模式；打开系统配置/后台管理。
- 预期：模型列表和默认模型正确；切换影响下一次请求；配置加载失败有提示且不白屏；普通用户不能修改系统配置。

#### SYS-02 后台管理页签

- 角色：`SYS_ADMIN`
- 前置：管理员有数据源和全局 SQL 历史权限。
- 操作：打开后台管理，切换数据源和全局 SQL 历史页签，关闭再打开。
- 预期：页签内容和各自 loading 状态独立；切换后加载一次；关闭后重新打开数据刷新；普通用户不能通过普通页面复用管理数据。

#### SYS-03 普通查看与 admin 管理接口分离

- 角色：`USER_A`、`SYS_ADMIN`
- 前置：公共数据源和字段字典可用。
- 操作：普通用户打开数据源、语义模型和字段字典查看；管理员打开系统管理并修改。
- 预期：普通页面只调用普通 GET/CRUD 入口；系统管理页面调用 admin 入口；普通用户查看不会因 admin 权限不足报错；普通用户不能通过网络重放 admin 写请求修改系统数据字典。

### 4.16 页面稳定性与异常回归

#### ST-01 重复点击和幂等

- 角色：全角色
- 前置：打开任意包含异步按钮的模块。
- 操作：快速重复点击保存、同步、预览、执行、停止、删除、发布、刷新。
- 预期：只产生一个有效操作；按钮 loading/disabled 正确；不会重复任务、面板、模型、技能或删除请求。

#### ST-02 关闭、返回和未保存变更

- 角色：全角色
- 前置：在数据源、语义模型、Builder、技能、看板弹窗中修改但不保存。
- 操作：点击取消、关闭、返回、切换对象和浏览器后退。
- 预期：有未保存提示；确认离开后丢弃编辑态，取消离开继续编辑；已保存数据不被临时草稿污染。

#### ST-03 网络、超时和权限失败

- 角色：全角色
- 前置：模拟接口 4xx、5xx、超时、断流和权限失败。
- 操作：在加载、保存、执行、停止、预览、上传和下载期间触发失败。
- 预期：错误提示可读，loading 能结束，按钮可重试；不展示后端堆栈，不把失败数据写入页面或历史；SQL 运行页按约定展示完整 SQL 错误。

#### ST-04 刷新与恢复

- 角色：全角色
- 前置：分别在查询、评估、上传、文件预览、看板刷新、技能编辑期间刷新浏览器。
- 操作：刷新、重新进入当前模式、切换历史会话。
- 预期：已持久化内容恢复；进行中任务显示真实可恢复状态或明确丢失；不会显示旧响应覆盖新内容；不产生重复提交。

#### ST-05 响应式和长内容

- 角色：全角色
- 前置：准备长 SQL、长 JSON、长字段名、长技能文件、大表格和多面板看板。
- 操作：在桌面、窄桌面和移动宽度下打开并操作。
- 预期：文本、按钮、表格和弹窗不重叠；横向/纵向滚动可用；右侧控制台、结果面板、工具详情和编辑器均可访问；无内容被静默截断。

#### ST-06 浏览器控制台与重复请求检查

- 角色：全角色
- 前置：清空应用自身错误日志，忽略浏览器扩展注入脚本。
- 操作：完整执行本基线主流程，观察 Network 和 Console。
- 预期：无 ChatData 自身未处理异常、循环请求和重复接口；扩展脚本报错不能作为应用通过依据，也不能把扩展错误误判为业务失败；失败用例必须能定位到实际请求和响应。

## 5. 发布执行记录

每次发布至少记录以下内容：

| 项目 | 内容 |
| --- | --- |
| 版本/提交 | 代码 commit、前端构建版本、后端部署版本 |
| 环境 | API 地址、数据库类型、执行器、`CHATDATA_ROW_LIMIT`、workspace backend |
| 账号 | 使用的角色和账号标识，不记录密码/token |
| 用例 | 按编号填写通过、失败、阻塞；失败必须关联缺陷 |
| 证据 | 关键页面截图/录屏、请求路径、结果状态、错误信息 |
| 未执行项 | 说明原因，不得用“未执行”标记为通过 |

发布通过条件：本基线中所有适用用例均为 `PASS`；不适用项必须由负责人说明原因并单独审批；任何权限越权、结果状态误报、查询数据丢失、已发布技能不可加载、公共资源被普通用户修改等问题都不能带缺陷发布。
