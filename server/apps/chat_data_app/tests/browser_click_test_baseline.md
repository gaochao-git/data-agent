# ChatData 浏览器点击测试基线

> 本文档只维护浏览器测试用例、前置条件和判定标准，不记录每轮执行结果。执行结果写入 `browser_click_test_runs/<date>.md`。
>
> 每条用例都必须通过页面操作完成；执行时记录页面结果、关键请求路径和最终状态到执行报告。
>
> 这不是 API 单元测试清单。后端接口、数据库、LLM 和执行器的纯接口契约仍由 `tests/api/` 与 `tests/unit/` 覆盖；本基线只验证用户从页面能完成的功能，以及页面是否调用了正确的权限入口。

## 1. 产品功能地图与端分类

### 1.1 产品功能分层

ChatData管理端负责系统级资源治理，业务端负责日常查询、分析和产物使用，其上层还有一个 Java Controller 服务会进行权限管控，权限通过后通过 Proxy 路由到我们的服务，路由标识我们在 Controller 设置了agents:chatData:admin、agents:chatData:common进行标识和路由，具体的请求为：
用户请求路径：
-> 浏览器页面
-> Java Controller：控制登录、权限校验
-> Proxy：携带 service token、用户身份转发
-> ChatData service：校验 service token 和用户身份，执行业务权限

管理端的公共数据源和语义模型治理结果，是业务端查询和 Builder 的可用基础；业务端产生的查询结果、文件、Office 文档和看板属于业务使用产物。`ENT-*` 和 `ST-*` 是分别在两个端执行的入口及稳定性检查，不是第三个产品端。会话与上下文、会话文件与产物、技能（含技能使用与技能管理）、定时任务（含管理端调度治理）均归属数据智能体子功能；其中会话是页面级容器，会话的新建、切换与刷新恢复会连带影响文件树、查询结果路径等跨模式状态，会话**不提供删除入口**（保留用于审计，见执行记录 DEF-02），侧栏「置顶」即复用收藏能力、置顶项排序置前；技能管理不依赖会话，入口在侧栏与输入栏“更多操作”菜单；定时任务由后端调度器在绑定会话内自动执行一次智能问数，用户侧入口在会话侧栏，管理端入口在后台管理「定时任务」页签。会话置顶属于会话管理，不属于 `FAV` 收藏。

### 1.4 测试用例的分解方式

每个模块按以下顺序设计用例，避免只测“主流程成功”：

1. **进入与可见性**：页面能否打开，角色能看到哪些资源和操作。
2. **配置与持久化**：新建、编辑、保存、取消、删除，刷新后是否一致。
3. **核心执行**：模块的主要业务动作是否完成，输入、输出和状态是否正确。
4. **跨模块联动**：上游配置是否能被查询、看板、历史、文件或 Agent 正确消费。
5. **权限与数据隔离**：普通、管理员、不同用户、无权限和权限回收场景。
6. **异步与失败恢复**：loading、重复点击、取消、超时、断流、部分成功和重试。

后续用例中的“前置、操作、预期、边界、关联”分别对应上述分解，编号前缀对应本节模块目录。新增页面功能时，必须先补本节功能范围和覆盖矩阵，再新增详细用例。

### 2.2 前置数据

- 至少准备一个 MySQL 数据源组、一个 Hive direct 数据源组和一个 Hive HTTP 数据源组；无法连接某类真实数据源时，使用测试环境的可控 mock，但仍保留该页面流程。
- 至少准备一个多成员数据源组，并为成员设置不同的 `member_name`、权限和可观察的成功/失败结果。
- 表结构至少包含：主键、唯一键、普通索引、时间列、数值列、枚举/状态列、无备注列、含中文备注的表和字段、可自关联的层级表。
- 准备一个系统公共语义模型、一个普通用户公共模型、一个 `USER_A` 私有模型、一个 `USER_B` 私有模型；准备一个自动生成的基础模型（默认启用），以及一个手工禁用的模型。
- 准备历史学习记录、评测用例、成功/失败/取消的 SQL 历史、收藏 SQL、个人看板、公共看板和未发布技能草稿。
- 定时任务需要：一个已启用的当前用户任务（周期 cron）、一个单次任务（执行时间设为近未来 2~5 分钟）、一个已停用任务、一个绑定会话已被删除的任务、一个含失败执行的执行历史；管理端还需要跨用户任务与至少一条「执行中」实例，以及一个可把调度暂停后恢复的窗口。
- 会话侧栏需要：同一用户 ≥25 条会话（覆盖刚刚结束/几分钟前/数天前三种时间）、至少两条已「置顶」会话、跨两个数据源的会话（用于分组视图）、以及一个标题命中关键词的长列表（用于搜索）。
- 准备文本、Markdown、CSV、TSV、JSON、DOCX、PPTX、XLSX、PDF、空文件、损坏文件和不支持格式的测试文件。
- 准备小查询结果、大于页面展示上限的查询结果、总行数可统计和总行数不可统计的文件。
- 准备可写的测试数据源、不可写或故意失败的数据源，以及可模拟网络超时、权限失败和保存失败的测试开关。

### 2.3 统一验收规则

- 页面打开、切换、关闭、刷新后无白屏、无限 loading、明显布局溢出或未处理异常。
- 保存、同步、执行、停止、删除、发布等操作只产生一次请求；按钮在请求期间不可重复提交，完成后状态与列表一致。
- 仅允许系统管理员操作系统级资源。普通用户的私有资源由 `user_id/owner` 隔离，公共资源可查看但不能修改原件。
- 字段字典的普通用户查看必须走 `/datasources/...` 普通 GET 接口；修改、AI 生成、枚举维护必须只在系统管理页面走 `/admin/datasources/...` 管理接口。不能以 admin 接口作为普通用户查看接口。
- 查询结果统一按 `results[]` 展示；每个成员核对 `member_datasource_id`、`member_name`、`status`、`sql`、`columns`、`data`、`total_count`、`execution_time_ms`、`error`。
- 查询结果写入 `outputs/query_result` 后，页面展示摘要和结果路径；智能体要回答具体数值、比较、分析或判断空结果时，必须继续从 `result_path` 读取文件，不能把“模型未直接看到结果”当成查询失败。
- 查询执行成功与结果交付成功分开核对。保存失败时检查 `query_status=succeeded`、`delivery_status=persistence_failed`，小结果按约定有限内联，大结果明确提示结果保存失败，不能伪装为普通截断或无条件重跑查询。
- 任何权限失败、数据源不存在、网络失败、模型失败和工具失败都要有用户可读提示；除 SQL 运行接口外，不向前端直接展示后端堆栈。
- 浏览器自动化点击前必须做可见性过滤：语义面板场景存在两类隐藏 0×0 副本按钮（① `pages/index.vue` 对 `SemanticConfigPanel` 的双挂载——内嵌用户面板 `:1520` 与全屏 admin 面板 `:1869` 同名按钮各一份；② 未打开 `el-dialog` 的预渲染 DOM，确认弹窗按钮常驻 `display:none` 的 `.el-overlay` 内）。按文本选择器直点会命中隐藏副本静默落空，表现为「点了没反应」且无报错。统一口径：枚举全部匹配后按 `getBoundingClientRect().width>0 && height>0` 过滤，或 `elementFromPoint` 命中测试后再点。
- 每条用例执行后把结果记录到执行报告（`PASS/FAIL`、角色、环境、时间、页面截图或录屏、关键请求、实际结果和缺陷编号），不修改本文件的用例定义。

## 4. 详细功能用例

### 4.1 页面入口与权限

#### ENT-01 页面模式切换

- 角色：`USER_A`
- 前置：拥有可用数据源和执行对象；`CHAT_DATA_USER_SEMANTIC_MODEL_ENABLED=true`（功能开关默认关闭，「语义模型配置」页签整页隐藏，此时只有四个模式）。
- 操作：打开 ChatData，依次切换数据智能体、可视化查询、SQL 查询、数据看板、语义模型配置；切换数据源、语义模型和执行对象。
- 预期：开关关闭时页签栏只有四个模式、无「语义模型配置」；开关打开并刷新页面后五个模式都能加载；模式、数据源、语义模型、执行对象状态互不串台；切换后不会重复提交上一个模式的查询。
- 边界：数据源为空时显示空状态，不自动执行查询；刷新后仍进入配置的默认模式。
- 关联：`web-vue/src/views/chat-data/pages/index.vue`；`GET /config`、`GET /datasources`。

#### ENT-02 管理入口可见性

- 角色：`SYS_ADMIN`、`USER_A`、`NO_SCOPE_USER`
- 前置：分别登录三种账号。
- 操作：打开页面并查看后台管理（含数据源管理、系统语义模型、全局 SQL 历史、定时任务、运行配置页签）。
- 预期：管理员可打开后台管理；普通用户和无权限用户不显示或不可操作管理入口；普通用户仍可进入自己的查询、私有模型和个人看板。
- 边界：仅隐藏按钮不算通过，需确认直接调用 admin 地址返回无权限；普通查看接口不能误走 admin 地址。
- 关联：`ChatDataAdminManager.vue`；`/admin/**` 路由。

#### ENT-03 无权限与权限回收

- 角色：`NO_SCOPE_USER`、`REVOKED_USER`
- 前置：无权限账号或先回收一个执行对象/机构权限。
- 操作：刷新页面，打开历史会话、SQL 历史、看板和语义模型，尝试重新执行已有查询。
- 预期：无权限对象不可选择；历史数据可以按权限显示，但不能绕过当前权限再次执行；页面展示空态或无权限提示。
- 边界：并发请求返回无权限时不出现白屏，不把旧的可执行状态保留为可用。

#### ENT-04 页面状态恢复

- 角色：`USER_A`
- 前置：在四个模式分别配置筛选条件、文件选择和右侧面板状态。
- 操作：切换模式、关闭再打开右侧控制台、刷新浏览器、切换历史会话。
- 预期：允许恢复的会话消息、工具调用、查询结果、文件树和预览状态恢复；新会话不继承旧会话的查询和文件选择。

#### ENT-05 页面、弹窗与悬浮窗三种接入形态

- 角色：`USER_A`、`SYS_ADMIN`
- 前置：主项目分别以路由页面、`ChatDataDialog` 弹窗、`ChatDataFloat` 悬浮窗三种方式接入 ChatData，并传入 `parentComponentName` 用于数据源模块映射。
- 操作：在三种形态下分别打开数据智能体与可视化查询，切换模式、发起一次查询、关闭再打开；弹窗形态下调整初始宽高，悬浮窗形态下最小化/还原与拖拽。
- 预期：三种形态都能加载同一套功能，模式与资源选择状态互不串台；`parentComponentName` 命中模块映射时默认数据源按映射生效，传空或未命中时回退权限内默认数据源而非报错；关闭（弹窗）或最小化（悬浮窗）不产生残留的查询任务与流式连接，重新打开后按各自形态恢复或重新初始化；三种形态切换不会重复提交上一形态的查询。
- 边界：弹窗/悬浮窗容器小于业务端布局最小宽度时，输入栏与内容区仍可用（配合 ST-05 响应式）；`parentComponentName` 指向不存在模块时不白屏，给出可读提示。
- 关联：`pages/index.vue`、`pages/ChatDataDialog.vue`、`pages/ChatDataFloat.vue`、`pages/README.md`；ENT-01 模式切换。

### 4.2 数据源管理

> 管理页面对应 `datasource_admin.py`；普通查询页面只读数据源和字段字典对应 `datasource_public.py`。本节所有管理用例均需同时核对权限和请求路径。

#### DS-01 数据源列表与空态

- 角色：`SYS_ADMIN`、`USER_A`、`NO_SCOPE_USER`
- 前置：准备有数据源、无数据源和无机构权限三种环境。
- 操作：打开数据源管理或查询页面的数据源选择器。
- 预期：管理员列表显示数据源组及成员；普通用户只显示有权限的数据源和执行对象；无权限用户显示空态或权限提示，不显示其他用户对象。

#### DS-05 拉取表信息与同步元数据

- 角色：`SYS_ADMIN`

#### DS-06 模块映射

#### DS-07 表分组和表选择

#### DS-08 表业务说明

- 角色：`SYS_ADMIN`
- 前置：存在已同步的表。
- 操作：编辑表业务说明，保存；再次编辑后取消；在语义模型和问数中确认说明可见。

#### DS-09 字段字典查看权限

#### DS-10 字段字典维护与 AI 生成

- 预期：字段字典保存和回显正确；AI 生成只是填充编辑表单，必须人工确认后保存；取消不保存；生成失败保留原值并给出提示；不修改物理表备注。

#### DS-11 表索引查看与维护

#### DS-12 健康检查（2026-10-19 更新：两级检查弹窗 `SemanticHealthModal`）

- 角色：`SYS_ADMIN`
- 前置：准备连接正常、连接失败和部分成员失败的数据源；缓存表结构与至少一个语义模型。
- 操作：点击“校验语义模型/健康检查”（新弹窗入口 title 为「校验语义模型（缓存表结构漂移 + 模型引用完整性）」），查看两级检查结果与详情。
- 预期：弹窗按两级组织——① **物理库 ↔ 缓存表**：检查数据源缓存中的表和字段在真实物理库中是否仍存在、类型是否变化；② **缓存表 ↔ 语义模型**：检查语义模型指标/维度/关联引用的表字段是否仍存在。每级状态徽标可区分正常（绿）/异常（红）；无异常时展示空态文案；异常项列出可读错误与检查时间；检查期间不能重复发起。普通用户对个人模型有对应只读入口时口径一致。

- 预期：取消不改变列表；确认有 loading，成功后数据源、执行对象和可选项消失；有关联资源时展示明确影响或阻止原因；失败不从页面假删。

- 前置：账号无管理员白名单。
- 操作：直接访问后台管理入口并尝试新建、修改、字典保存、索引保存、删除。
- 预期：入口隐藏或打开即提示无权限；所有 admin 写接口拒绝；普通用户仍可使用普通数据源和字典查看接口。

### 4.3 语义模型配置

#### SEM-01 模型列表与作用域

- 角色：`SYS_ADMIN`、`USER_A`、`USER_B`
- 前置：准备系统公共、用户公共、两份私有模型；普通用户入口需 `CHAT_DATA_USER_SEMANTIC_MODEL_ENABLED=true`（关闭时前台无「语义模型配置」页签，管理员仍从「后台管理 → 模型」进入同一面板）。
- 操作：分别打开系统管理和普通用户语义模型入口，切换模型列表。
- 预期：管理员可管理系统公共模型；普通用户可查看可用公共模型和自己的私有模型；`USER_A` 看不到或不能修改 `USER_B` 私有模型；模型来源、维护人和启用状态清晰。
- 边界：没有模型时显示空态，不自动创建。

#### SEM-02 创建私有模型

- 角色：`USER_A`
- 前置：普通用户有可用数据源。
- 操作：点击新建语义模型，填写名称、描述，保存；尝试空名称、重复名称、超长名称和非法字段。
- 预期：只创建 `USER_A` 私有模型；校验失败不保存；新模型可在本人查询入口选择，不能被 `USER_B` 选择。
- 关联：`POST /datasources/{id}/semantic-configs`。

#### SEM-03 创建和编辑公共模型

- 角色：`SYS_ADMIN`
- 前置：进入管理员模型管理。
- 操作：新建公共模型，填写名称、描述、查询规则、推荐问题，保存；编辑后保存、取消。
- 预期：公共模型可被授权用户查询和 Builder 选择；普通用户不能修改公共模型；取消恢复服务端值；重复保存不产生版本或重复记录。
- 保存前校验（2026-09-27 起）：点保存先调 dry-run 校验——结构错误直接 toast 拦截不落库；有质量提示（单模型规则/跨模型口径 `CON_CROSS_MODEL_*`）弹「保存前校验」弹窗列出 `[编码] 消息`，确认「仍要保存」才落库、「去修改」关闭不保存；无提示时静默直接保存。与 Ossie 导入「先校验再确认」同一交互。
- 关联：`POST /datasources/{id}/semantic-configs/validate`、`POST /admin/datasources/{id}/semantic-configs/validate`、`PUT .../semantic-configs/{config_id}`。

#### SEM-04 一键生成基础单表模型

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：数据源中有尚未建模的物理表。
- 操作：管理员点击“模型初始化”，选择单表或批量生成；普通用户尝试相同操作。
- 预期：只有管理员可以调用生成接口；每张表生成一个基础模型；生成模型默认启用；表字段、主键、唯一键、物理类型和表列关系正确；字段备注为空时不阻塞生成，后续可人工补充；已存在模型不重复生成。
- 边界：无新表、部分表失败、重复点击、连接失败均有明确结果；普通用户不显示或不能操作该按钮。
- 管理端新顶栏入口（2026-10-19，`b05e2afb`）：后台管理语义模型面板顶栏新增「批量初始化」按钮（title「为尚未建模的物理表初始化基础模型（默认启用）」），与顶栏的数据源组选择器、语义模型选择器、「批量启动/批量暂停」（SEM-19）同排；点击后仅对尚未建模的物理表生成基础模型，已建模表跳过。
- 关联：`POST /admin/datasources/{id}/semantic-configs/generate-basic`。

#### SEM-19 批量启动与批量暂停

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：数据源下存在多个语义模型，且启用/禁用状态混合；个人维护页（`USER_A`）至少有两个本人私有模型。
- 操作：管理员点击头部“批量启动”与“批量暂停”（`title` 分别为「批量启动选中的语义模型」/「批量暂停选中的语义模型」；2026-10-19 起管理端入口在后台管理「语义模型管理」面板顶栏 `SemanticModelAdminPanel`，与数据源组选择器、模型选择器、「批量初始化」同排），在弹窗中确认默认勾选集合、搜索过滤、全选/取消全选后确认；普通用户在个人维护页对本人私有模型执行同样操作。
- 预期：
  - 弹窗标题随入口变化（批量启动语义模型 / 批量暂停语义模型），只列出 `can_manage !== false` 的模型；打开时默认勾选「当前状态与目标相反」的模型。
  - 确认后一次请求完成整批切换：`PATCH /datasources/{id}/semantic-configs/batch-toggle` 与 `PATCH /admin/datasources/{id}/semantic-configs/batch-toggle`（个人/公共两套入口）。
  - 返回 `updated_ids / skipped_ids / not_found_ids / updated_count`，提示形如「已启用 3 个指标集，1 个无权限，1 个不存在」；`updated_count > 0` 成功提示，为 0 时降级为警告提示。
  - 列表刷新后每个模型的启用状态与 `updated_ids` 一致；单条开关与批量开关状态口径一致。
  - 越权模型（普通用户操作公共模型、管理员操作他人私有模型）计入 `skipped_ids`，不中断整批；不存在的 ID 计入 `not_found_ids`。
  - 空勾选时确认按钮 disabled；单次最多 200 个，超出给出明确提示。
- 边界：全选后取消、搜索无匹配、列表为空时按钮 disabled、重复提交期间按钮禁用。
- 关联：`components/semantic/SemanticBatchToggleDialog.vue`、`routers/semantic_config.py`（`batch-toggle`）、`daos/semantic_config_dao.py`（`batch_update_enabled_async`）；与 SEM-05 同源（单条 toggle）口径必须一致。

#### SEM-05 启用、禁用和默认状态

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：存在默认启用的基础模型和手工禁用的模型。
- 操作：管理员复核后启用、再次禁用；普通用户尝试改变公共模型状态。
- 预期：禁用模型不进入智能体或 Builder 可选列表；启用后可选择；普通用户不能改变公共模型状态；保存失败时页面状态回滚。

#### SEM-06 表范围和别名

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：模型包含多张关联表和层级表。
- 操作：选择表、移除表、全量查看表；拖拽调整表顺序或画布布局；设置表别名；切换表名/备注显示；点击表预览。
- 预期：范围、别名、拖拽布局和展示方式正确保存；移除表同步清理相关字段/关系或提示待处理项；表预览显示正确表和有限行数，不修改模型。

#### SEM-07 维度配置（维度勾选、新增维度与折叠）

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：表有物理字段、主键、唯一键、无备注列；多表关联模型中存在跨表同名字段（如 users.user_id / orders.user_id）。
- 操作：查看维度配置区（表头应有 表/字段/[类型/列备注]/`维度`勾选列/逻辑类型/表达式/显示名称/字段备注/字段字典/操作，**勾选列决定该字段是否参与维度**）；勾选/取消某一行（优先用多表重复字段验证）；点击「新增维度」打开弹窗；编辑勾选行的逻辑类型、表达式、显示名称和业务含义；折叠与展开维度配置；在默认行与自定义行分别查看操作列。
- 预期：维度区一行 = 一个物理字段；副标题计数「已选 X/Y」随勾选联动（X=已勾选参与维度的行数、Y=物理字段总行数，取消勾选 X 即减 1）；**未勾选行不参与维度重名判定与保存**（应用字段设置只写入勾选行），未勾选行的逻辑类型/表达式置灰禁用；多表重复字段（如两侧关联键显示名相同）取消一侧勾选后，显示名称重复红色报错消失、可正常保存，刷新后勾选态按已保存 dimensions 持久化（有该物理列条目=勾选）；会话内新拖入的表默认全勾，应用字段设置后按持久化结果推导；折叠后表格整体隐藏且按钮文案切为「展开维度配置」；「新增维度」弹窗只提供 `维度` 一种类型，无指标 tab；物理列名、表名和物理类型可追溯；无备注字段允许保存空业务备注；字段缺失或物理列不存在时明确标记，不生成不可执行配置；**默认物理列行不显示删除按钮（该行无法真正删除，避免死交互），仅自定义行与物理列已消失的行可删**。
- 关联：`SemanticConfigPanel.vue`、`components/semantic/AddFieldDialog.vue`；SEM-08 表达式、SEM-12 指标管理。

#### SEM-08 表达式和自由 SQL

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在维度和指标字段。
- 操作：打开表达式编辑器，修改表达式并保存；取消修改；为自由 SQL 指标填写 `rightExpression`；再次执行查询。
- 预期：表达式只在点击保存后更新；取消不影响主配置；`rightExpression` 能在 DSL/SQL 查询中保留并按语义内核编译；原生只读 SQL 仍按 SQL 模式处理，不把表达式误当物理字段。

#### SEM-09 指标聚合扩展

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在数值字段，且该模型有一个**简单聚合原子指标**（表达式为 `SUM/AVG/MAX/MIN(单列)`）。
- 操作：在指标管理区该指标行点击「扩展聚合指标」；查看候选行（选择/表达式/字段名/指标名称）与已存在标记；勾选候选项后确认/取消；在 Builder 中选择新指标。
- 预期：只有简单聚合原子指标行显示该入口（`COUNT`、派生、复合指标行不显示）；候选排除与当前指标相同的聚合方式，已存在的同字段同聚合标记「已存在」且不可勾选；确认后新增原子指标进入指标列表并提示「已扩展 N 个原子指标，保存后生效」（未点保存不落库）；取消不改变指标列表；非法聚合、空表达式和重复名称被阻止。
- 关联：`SemanticConfigPanel.vue`、`components/semantic/MetricExpandDialog.vue`；SEM-12、SEM-16、SEM-17。

#### SEM-10 表关系与自关联

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：存在主子表和层级自关联表。

#### SEM-16 派生指标扩展

- 角色：模型所有者或 `SYS_ADMIN`（管理端公共模型与用户私有模型两个入口分别验证）
- 前置：模型已存在至少一个聚合原子指标（如 `SUM` 销售额）、一个 logical_type 为 date/datetime 的时间维度和一个普通维度。
- 操作：在指标管理区点击「新建指标」，切到「派生指标」tab 新建派生指标：选择基础指标、统计周期（今日/昨日/近 N 天/本周/本月/自定义 between）和修饰词过滤，保存；编辑后保存、取消；删除并分别取消/确认；在无原子指标的模型上点击新建；分别尝试非法配置：基础指标不存在/仍是派生/是复合/非聚合表达式、周期维度不是时间维度、between 缺 start/end 或 end 早于 start、过滤维度不存在、IN/BETWEEN 缺筛选值、显示名称与现有指标/维度重复。
- 预期：合法配置保存成功并在列表展示人类可读口径（基础指标 · 周期 · 过滤）；派生指标不配置 expression/table，不出现在字段物理配置行中；表作用域收缩和应用字段设置不会误删派生指标；所有非法配置被阻止并给出具体原因，取消不落库；删除有确认。
- 边界：无聚合原子指标时新建入口提示先创建原子指标；同一派生指标名不可与指标/维度重复；删除被查询引用的基础原子指标时，保存校验需给出明确报错而不是静默破坏口径。
- 操作符全集：过滤操作符下拉应与后端权威集合一致（=、!=、<>、>、<、>=、<=、IN、NOT IN、LIKE、NOT LIKE、STARTS WITH、ENDS WITH、BETWEEN、IS NULL、IS NOT NULL、EMPTY STRING）；IS NULL/IS NOT NULL/EMPTY STRING 选中后隐藏筛选值输入框；BETWEEN 要求起止值逗号分隔且缺一报错；IN/NOT IN 多值逗号分隔；小写操作符保存后归一为大写。
- 混用周期拦截：同一查询（问数或 Builder）同时使用两个不同周期的派生指标（如 本月成交额 + 近7天下单量）时，执行返回明确报错「不支持混用不同周期的派生指标」；同周期派生指标（如两个本月口径）可正常同查。
- 保存分型校验：直接提交结构错配的配置被请求模型拒绝——派生指标带非空 expression、派生指标缺 base_metric、原子指标带 formula/period/filters、原子指标带 base_metric 但无 compare_type/compare_mode。
- 跨模块联动：在问数和 Builder 中查询含派生指标的模型，核对编译 SQL 按基础指标表达式叠加固定周期/过滤（半开区间），结果与手工加同样过滤的查询一致；多成员结果结构与普通指标一致。
- 关联：`SemanticConfigPanel.vue`、`components/semantic/AddFieldDialog.vue`；SEM-09 聚合扩展、SEM-15 保存校验；BI-10。

#### SEM-17 复合指标扩展

- 角色：模型所有者或 `SYS_ADMIN`
- 前置：模型存在同表的多个聚合原子指标（如 销售额、订单数）。
- 操作：在指标管理区点击「新建指标」，切到「复合指标」tab 新建复合指标，输入公式（如 `{销售额} / {订单数}`）保存；编辑公式、删除；分别尝试非法配置：公式无 `{指标}` 引用、含四则运算/括号/数字以外字符、引用不存在的指标、引用其他复合指标、引用派生指标、引用非聚合指标、成员指标跨表。

- 预期：合法公式保存成功并在列表展示公式口径；非法配置逐一被阻止并指明原因（尤其跨表与嵌套引用）；复合指标不出现在字段物理配置行中；删除被引用的成员指标时保存校验报错明确。
- 跨模块联动：在问数和 Builder 中查询复合指标，核对编译 SQL 将 `{引用}` 代入成员聚合表达式、除号后的引用自动包 `NULLIF(..., 0)` 防除零，除数为 0 的分组返回空值而非报错；指标卡/结果展示使用派生指标名。
- 关联：`SemanticConfigPanel.vue`、`components/semantic/AddFieldDialog.vue`；SEM-09、SEM-16；BI-10。

#### AG-13 消息队列与插队执行

- 角色：`USER_A`
- 前置：打开数据智能体会话，准备可控耗时的查询任务。
- 操作与预期（按四个子场景顺序验证）：
  - **运行中入队与策略切换**：流式生成期间连续发送多条消息；每条队列项可在“立即插入”（next-step，注入当前步骤）和“下一轮”（next-turn，留给后续 Run）之间切换；编辑和移除即时生效且刷新后一致。
  - **多轮链式自动接续**：当前轮完成后，下一轮队列消息无需用户操作自动开始执行，轮次连续推进；接续延迟无感知（不出现长时间“等待处理”停滞）；全程输入框保持“继续输入任务”状态。
  - **停止后队列保留与单条执行**：运行中点停止后，队列消息原样保留并出现「执行」按钮；点击单条「执行」只将该条消息作为新任务启动（其余继续排队），不合并其他队列内容；执行后该消息从队列消失、升级为对话中的新轮次。
  - **停止后发送不合并队列**：会话已停止且有遗留队列时，从输入框发送新消息，新输入单独成轮立即执行，遗留队列不被合并进同一次调用；当前任务结束后队列按 FIFO 自动续跑。
- 边界：
  - 「执行」按钮仅在 `status === 'pending'` 且会话空闲（无运行中任务）时可见；流式生成期间不得出现或闪现（含点击发送到 run_created 事件到达之间的空窗）。
  - 运行中队列项的出口是“立即插入/转下轮”切换，不是单独执行；两个入口互斥。
  - waiting_user（等待回答问题）时「执行」不可见，必须先恢复对话。
  - 刷新页面后，队列内容、顺序、策略与会话运行状态与服务端一致；遗留队列在页面恢复后仍可执行。
  - 队列消息被消费（claimed/consumed）后不可再编辑策略或执行。
- 关联：AG-11 停止语义；RUN-01 任务生命周期。

- 关联：AG-13 消息队列（steer 实时接纳链路）；FILE-01 工作区文件树与目录隔离；`WorkspaceFileMentionMenu.vue`、`useWorkspaceFileMention.ts`、`ConversationMessageList.vue`。

### 4.6 会话文件、查询结果和产物

#### FILE-01 上传与目录隔离

- 角色：`USER_A`
- 前置：打开一个会话。
- 操作：上传文本、Office 和不支持格式文件；在文件树刷新；尝试选择 `workspace`、`uploads`、`outputs`、`outputs/query_result`、`outputs/.tool-offload`。

#### FILE-02 文本和结构化文件

- 角色：`USER_A`
- 前置：已有 TXT、MD、CSV、TSV、JSON、YAML 文件。
- 操作：点击文件，查看预览和源码；下载；对 CSV/TSV/JSON 查看表头、内容和格式错误。
- 预期：内容、编码、换行和 Markdown 渲染正确；源码/预览切换不改文件；损坏文件显示可读错误，不白屏。**YAML 预览（2026-09-18 起，`CodeFilePreview.vue`）**：`.yaml/.yml` 走 CodeMirror 只读高亮渲染（`yaml()` 语言包），预期出现 `.cm-editor`、行号 `.cm-lineNumbers`、行内存在被高亮包裹的 token span（默认高亮用哈希类名，不产出 `.cm-propertyName` 等语义类）、`contenteditable="false"`；文件名截断不影响判定。其余类型（json/csv/txt 等）仍走原有分支（表格/纯文本），不得被 yaml 分支劫持。**高亮样式口径（2026-09-18 17:08 起）**：`vue-codemirror` 对所有编辑器强制注入 `basicSetup`（含 `defaultHighlightStyle`）——**SQL 编辑器与 YAML 预览统一走 CodeMirror 默认调色板**（keyword 紫红/string 红/number 绿），`CodeFilePreview.vue` **不再挂自定义 `HighlightStyle`**（初始版的 Apple 配色方案已按用户决策移除，避免两套高亮样式叠加）；`SqlEditor.vue` 里 `.cm-keyword{color:#1677FF}` 等自定义配色 CSS 为死样式（tag class 不产出，视觉≠注释口径，非功能缺陷）。重复 `lineNumbers()` 已实测被去重，无双列。

#### FILE-04 文件重复点击和内容刷新

- 角色：`USER_A`
- 前置：文件可预览且 Agent 会修改同一工作区文件。
- 操作：连续点击同一文件两次；在 Agent 写入前后点击文件并刷新文件树/预览。
- 预期：第二次点击仍能获取内容，不出现“暂无可预览内容”的错误假状态；内容变化后再次请求得到新内容；请求中的旧响应不能覆盖更新后的内容；加载状态稳定，不反复闪烁。
- 刷新语义（**2026-09-18 起，`conversation/Conversation.vue`**）：预览区头部刷新按钮（`data-console-files-refresh`，`v-if="selectedConsoleFile"` 时才渲染，title 「刷新文件列表与预览内容」/ 加载中「正在刷新」）**同时刷新文件列表与强制重载当前预览内容** —— 列表刷新不会作废预览内容缓存（见 `utils/workspacePreviewCache.ts`），只刷列表会让人以为「点了刷新但预览还是旧的」。判据：点击后同时发出 `workspace-files` 与文件内容请求（XHR 探针可证）。
- 自动重载：Agent 工具改写的文件**恰是当前预览文件时**，工具 `completed` 即刻 `forceReload` 预览内容，不等用户手动点刷新（`reloadWorkspacePreviewIfSelected`，路径候选统一由 `utils/toolDisplay.ts` 的 `extractWrittenFilePathCandidates` 提取，含 `file_path`/`target_path`/`destination_path`/`path`/`action_payload.save_as`/`files[]`，单测见 `toolDisplay.spec.ts`）。**覆盖缺口（非缺陷，回落到手动刷新）**：`bash_run`/`officecli_run` 的间接写入（命令文本无结构化路径）不在自动重载范围内。刷新按钮忙碌态绑 `isWorkspaceRefreshBusy`（列表请求 + 当前预览内容请求任一进行中）。

### 4.8 统一查询执行与结果交付

> `RUN-*` 不是新的用户页面，而是智能体、SQL 查询、Builder 和看板共同依赖的执行层。这里的用例必须至少从两个不同入口重复验证，确保共享能力没有被某个入口单独改出另一套口径。

#### RUN-01 查询任务生命周期

- 角色：`USER_A`
- 前置：准备智能体、SQL、Builder 和看板各一条可执行查询。
- 操作：分别从四个入口发起查询，观察等待、执行、成功、失败、部分成功、取消和超时状态。
- 预期：所有入口使用统一任务状态和终态语义；状态变化不会跳过必要阶段或长时间停留 loading；刷新后能恢复已持久化状态；预览操作不创建执行任务。
- 边界：重复点击只创建一个任务；任务创建失败不显示为执行中；取消失败有明确提示。

#### RUN-02 多成员结果协议

- 角色：`USER_A`
- 前置：准备单成员、全成功多成员、部分成功多成员和全失败多成员数据源。
- 操作：从 SQL、Builder 和智能体分别执行同一查询，比较结果面板、工具结果和历史记录。
- 预期：均以 `results[]` 表达成员结果；每个成员的 `member_datasource_id`、`member_name`、`status`、`sql`、`columns`、`data`、`total_count`、`execution_time_ms`、`error` 字段语义一致；成功成员数据不因其他成员失败而丢失。
- 边界：成员名称相同但 ID 不同、成员部分失败和空结果均能区分；前端不重复展示外层结果和成员结果。

#### RUN-03 全局行数限制

- 角色：`USER_A`
- 前置：配置 `CHATDATA_ROW_LIMIT=10000`，准备无 limit、较小 limit、超过上限和带 offset 的 SQL/DSL/Builder 查询。
- 操作：从 SQL、Builder 和智能体分别提交查询，查看实际 SQL、结果行数和结果文件。
- 预期：所有入口采用同一全局上限；用户声明的 limit 不能绕过上限；结果摘要、`total_count`、实际返回数据和文件内容相互一致；offset 不改变上限口径。
- 边界：非法 limit、负 offset、极大整数和空值均被校验；不能因为某个页面参数名不同而绕过公共限制；SQL 末尾注释导致系统无法安全追加行数上限时，执行被拒绝并提示可行动的修正方式（如把注释移到 LIMIT 之前），不产生无界查询。

#### RUN-04 结果落盘与后续消费

- 角色：`USER_A`
- 前置：准备小结果和大结果，workspace backend 可写。
- 操作：从智能体、SQL、Builder 和看板分别执行；查看结果摘要、`result_path`、文件树、历史结果和看板面板；对智能体结果继续请求数值分析。
- 预期：查询结果统一落到 `outputs/query_result`；页面展示摘要和路径，后续工具可按路径读取；智能体在需要具体结论时先读取结果文件；历史和看板消费的字段、成员、SQL 与原查询一致；内部目录不误作为普通产物。

#### RUN-05 结果保存失败交付

- 角色：`USER_A`
- 前置：模拟 workspace backend 保存失败，分别准备小结果和大结果。
- 操作：从至少两个查询入口执行并观察工具结果、结果面板、历史和看板。
- 预期：小结果按有限内联策略返回并标记 `content_in_context=true`、`result_persisted=false`；大结果显示“查询执行成功，但结果保存失败”；同时有 `query_status=succeeded`、`delivery_status=persistence_failed`；前端不显示普通查询成功，不无条件重跑数据库查询。
- 边界：保存恢复后下一次查询可正常落盘；失败的旧结果不会被错误复用为新查询结果。

#### RUN-06 取消、刷新和结果一致性

- 角色：`USER_A`
- 前置：准备可控耗时的 SQL、Builder 和看板查询。
- 操作：执行中取消并刷新；在任务终态后刷新、切换历史会话或重新打开看板。
- 预期：取消后的任务、历史、结果面板和看板状态一致；旧响应不能覆盖新任务；刷新不产生重复执行；已成功结果可回放，未完成结果不会伪装成功。

- 角色：`USER_A`
- 前置：配置 `CHATDATA_ROW_LIMIT=10000`。
- 操作：执行不带 limit、超过 10000、带合法较小 limit、带 offset 的 SELECT；执行 INSERT/UPDATE/DELETE、DDL、注释绕过和非法语句；执行带 `INTO OUTFILE/DUMPFILE`、`LOAD_FILE()`、`FOR UPDATE`、`SLEEP()` 的 SELECT；将查询超时设置为超过 3600 秒。

- 角色：`USER_A`
- 前置：当前语义模型包含派生指标和复合指标（SEM-16/17 已配置），Builder 字段面板可见。
- 操作：将派生/复合指标拖入指标区；观察指标 chip 形态；尝试将逻辑指标拖入维度区；将逻辑指标与普通聚合指标混用；配置过滤（HAVING）、排序后执行；收藏该 Builder 配置，重新打开并编辑；刷新页面后重新加载收藏。

- 边界：语义模型中删除派生/复合指标后，历史收藏重新执行给出可读失败，不静默编造空结果；逻辑指标与普通指标的结果展示走共享结果组件，字段口径一致。

### 4.17 定时任务

> 本节 `SCHED-*` 归属业务端数据智能体子功能。用户侧入口在会话侧栏「定时任务」，管理端入口在后台管理「定时任务」页签；两侧共用执行历史表格组件（`AgentScheduleRunsTable.vue`），字段口径必须一致。定时任务按用户维度隔离（`user_id`），管理端可跨用户查看与强制启停。

#### SCHED-01 入口、列表与作用域

- 角色：`USER_A`、`USER_B`、`NO_SCOPE_USER`
- 前置：`USER_A` 有已启用周期任务、已停用任务、单次任务、绑定会话已被删除的任务；`USER_B` 各有自己的任务。
- 操作：在会话侧栏点击「定时任务」打开弹窗；hover「下次执行」「调度」列查看悬浮说明；用 `USER_B` 打开同一弹窗。
- 预期：弹窗只列出当前用户的任务，字段包含任务名称、会话、会话 ID、调度、下次执行、状态开关与操作菜单；`new_each_run` 任务在「会话」列显示「每次新建会话」，`fixed` 任务显示会话标题且点击可跳转到该会话（`openConversation`）；绑定会话已删除时显示「会话已删除」且悬浮提示「会话不存在」，不报错、不跳转；「调度」列悬浮显示「有效期至 …」或「长期有效」；「下次执行」为空显示 `-`；停用任务的「下次执行」为空；`NO_SCOPE_USER` 打开时列表为空并显示「暂无定时任务」，无其他用户数据泄漏。
- 边界：接口失败时列表保持上次数据并提示「获取定时任务失败，请稍后重试」，不白屏；弹窗打开只在首次拉取一次列表，重复开关不重复请求；任务较多时列表在限高内纵向滚动（表头固定），弹窗高度稳定不溢出视口。
- 关联：`AgentScheduleManager.vue`；`GET /agent-schedules`；SCHED-05 管理端全量列表。

#### SCHED-02 新建定时任务

- 角色：`USER_A`
- 前置：当前用户有历史会话、数据源组、可用模型（含支持推理与不支持推理各一）。
- 操作：点击「新建定时任务」，分别验证——
  - 运行会话：切「每次新建会话」与「指定历史会话」，在指定模式下从下拉选择会话；
  - 任务标题、指令、数据源组、模型、推理等级；
  - 调度：周期执行下依次选「每小时」（第 N 分）、「每天」（HH:mm）、「每周」（周几 + HH:mm）、「每月」（N 号 + HH:mm）、「自定义」（如 `0 9 * * 1-5`）；再切「单次执行」用日期时间选择器选近未来时间；每次切换档位或调整参数时观察调度行右侧的行内预览文案；
  - 有效期至：填一个时间、留空各一次；
  - 非法输入：空标题、空指令、指定会话模式不选会话、单次执行不选时间、指令超 2000 字、模型切到不支持推理的模型后看推理等级。
- 预期：任务创建成功并出现在列表，`cron` 预设能正确转成五字段表达式（每小时为 `<分> * * * *`、每天为 `<分> <时> * * *`、每周为 `<分> <时> * * 周几`、每月为 `<分> <时> <号数> * *`）；调度行内实时显示灰字行内预览并随档位与参数即时更新（每小时→「每小时的第 NN 分」、每天→「每天 HH:mm」、每周→「每周一、周三 HH:mm」、每月→「每月 N 号 HH:mm」、单次→「单次执行 · YYYY-MM-DD HH:mm」、自定义→cron 译文；周几未选时显示「请选择执行日」）；「指定历史会话」必须选会话才允许提交，未选时提示「请选择一个历史会话」；单次执行未选时间提示「请选择单次执行时间」；标题/指令为空分别提示「请填写任务标题」「请填写任务指令」；指令字数超限被 `maxlength` 拦住；切换模型会清空已选推理等级，不支持推理的模型下推理等级下拉禁用；「每次新建会话」创建出的任务在列表「会话」列显示「每次新建会话」；留空有效期表示长期有效。
- 边界：保存期间按钮 loading 且不可重复提交；保存失败保留表单内容并提示，列表不出现半成品；`cron` 自定义表达式非法时给出可读错误而不是静默创建。
- 关联：`AgentScheduleManager.vue`、`utils/agentSchedule.ts`；`POST /agent-schedules`。

#### SCHED-03 编辑任务与补丁式提交

- 角色：`USER_A`
- 前置：存在一个已配置数据源组 + 模型 + 推理等级 + 有效期的任务（用于验证「未改动不下发」）。
- 操作：打开编辑，逐项单独验证并每次保存后重新打开核对——
  - 只改标题 → 保存；
  - 只改指令 → 保存；
  - 清空数据源组 → 保存；
  - 清空有效期至 → 保存；
  - 修改调度（周期改每天、每天改自定义、周期改单次）；
  - 运行会话从「指定历史会话」切到「每次新建会话」再切回；
  - 取消编辑后再打开对比服务端值。
- 预期：编辑只下发与打开弹窗时基线不同的字段，**未改动的调度与运行配置不被表单默认值覆盖**（保存后重新打开，数据源组/模型/推理等级/有效期仍为原值）；清空数据源组与清空有效期能真正生效（保存后重新打开显示为空 / 「长期有效」），不是「清空后又被旧值写回」；只改标题时 `next_trigger_time` 不因「执行时间已过期」被重算或拦住（已过期的单次任务仍可改标题）；调度字段变更后 `next_trigger_time` 按服务端时钟重算；编辑回显时若绑定会话不在最近会话下拉里，用会话标题回显而不是回落到会话 ID；取消编辑不改变服务端值。
- 边界：切换运行会话模式但未选会话时提交被拦截；保存失败保留表单；重复点击保存只产生一次请求。
- 关联：`AgentScheduleManager.vue`、`utils/agentSchedule.ts`（`buildSchedulePatch` / `buildRuntimeOptionsPatch`）；`PUT /agent-schedules/{job_id}`；`schema.py` 的 `clear_effective_end_time`。

#### SCHED-04 启停、立即执行、删除与执行历史

- 角色：`USER_A`
- 前置：有一个启用任务、一个停用任务；一个绑定会话空闲、一个绑定会话正在流式生成；任务已有成功与失败两类执行记录。
- 操作：切换状态开关；对同一个任务快速连点「立即执行」；在绑定会话正忙时再次「立即执行」；打开「执行历史」核对字段并点击会话列复制；删除任务分别取消与确认；对已停用任务观察是否仍有触发实例。
- 预期：开关启停即时生效并刷新列表，启用后重新计算「下次执行」，停用后「下次执行」显示 `-` 且该任务未执行的触发被取消（不再有僵尸实例）；「立即执行」成功后提示「已触发执行，结果将写入绑定会话」，会话正忙时提示「会话正忙，已加入队列稍后自动执行」并转后台重试；同一时刻只允许一个在途触发请求（连点不产生多个手动实例）；执行历史展示状态、来源（手动/计划）、会话、计划时间、完成时间、耗时、Agent Run 状态与错误信息，手动触发来源显示「手动」；会话列点击可复制完整会话 ID；执行记录较多时弹窗高度稳定不溢出视口，表格表头固定、表体在限高内纵向滚动查看全部记录；删除前有确认框「确定删除定时任务「x」？删除后不再执行。」，取消无变化，确认后任务从列表消失且不再调度。
- 边界：执行历史为空显示「暂无执行记录」；失败记录有可读错误信息；已删除任务的执行历史不再可从用户侧入口进入；取消失败或删除失败有可读提示，不出现「页面上消失了但服务端还在调度」的假删。
- 关联：`AgentScheduleManager.vue`、`AgentScheduleRunsTable.vue`；`GET /agent-schedules/{job_id}/runs`、`POST /agent-schedules/{job_id}/trigger-now`、`DELETE /agent-schedules/{job_id}`。

#### SCHED-05 管理端概览与全局调度开关

- 角色：`SYS_ADMIN`、`USER_A`
- 前置：管理端可用；系统内有跨用户任务与至少一条「执行中」实例；准备一个可暂停再恢复的窗口。
- 操作：`SYS_ADMIN` 打开后台管理「定时任务」页签，核对四张统计卡与调度状态徽标；点击「停止任务调度」开关并在确认框分别取消与确认；暂停期间等待一个到点的任务观察是否触发；恢复后再次观察；`USER_A` 尝试打开同一页签。
- 预期：概览卡片展示「定时任务（启用中/总数）」「累计执行（含近 24h 次数）」「执行成功率（含失败/取消/跳过计数）」「执行中（排队/领取/执行中）」，成功率无数据时显示 `-`；调度状态徽标在运行/停止两种状态切换（含 `pause_reason`）；暂停前有确认框且文案明确「进行中的执行与已排队的触发不受影响」，取消不改变状态，确认后徽标变为「任务调度已停止」；暂停期间到点任务不再触发新的执行；恢复后调度继续，用户任务的启停状态未被全局开关改动；`USER_A` 打开页签被拒绝或入口不可见（配合 ENT-02 / SYS-03）。
- 边界：并发下开关只产生一次请求（`togglingPause` loading）；概览或列表任一接口失败时给出可读提示，不白屏、不展示陈旧数字为最新。
- 关联：`AgentScheduleAdminPanel.vue`、`ChatDataAdminManager.vue`；`GET /admin/agent-schedules/overview`、`PUT /admin/agent-schedules/pause`。

#### SCHED-06 管理端跨用户任务列表与强制启停

- 角色：`SYS_ADMIN`
- 前置：多个用户各有任务，其中包含停用任务、绑定会话已删除的任务与失败较多的任务。
- 操作：打开列表核对列；搜索一个标题关键词、再搜索一个用户名、清空搜索；点击「刷新」；翻页（下一页/上一页，搜索后翻页）；对他人任务切换状态开关。
- 预期：列表跨用户展示任务标题、绑定会话、创建人、调度、状态、执行次数、成功、失败、取消、最近执行（时间 + 结果徽标，未执行显示「未执行」）与「执行历史」入口；每行满足「成功 + 失败 + 取消 + 跳过 = 执行次数」的对账口径（跳过计入执行次数但无独立列时由概览卡体现）；搜索按标题或用户命中并在回车/清空时触发，搜索后回到第 1 页；列表走服务端分页（每页 20 条，底部显示总数与页码），翻页只请求当前页数据且行内容与页码一致；刷新重新拉取概览与当前页列表；管理端可强制启停任意用户的任意任务，操作后统计卡与当前页列表同步刷新且不跳页；失败数非 0 时以醒目样式展示。
- 边界：搜索无结果时显示「暂无定时任务」空态而不是保留旧数据；启停失败时列表回滚到服务端真实状态并提示；列表为空时不报错；总条数不足一页时分页器只显示总数不显示多余页码。
- 关联：`AgentScheduleAdminPanel.vue`；`GET /admin/agent-schedules`、`PUT /admin/agent-schedules/{job_id}/enabled`。

#### SCHED-07 管理端执行历史与权限边界

- 角色：`SYS_ADMIN`、`USER_A`、`NO_SCOPE_USER`
- 前置：存在多个用户的任务与执行记录，含失败与手动触发记录。
- 操作：`SYS_ADMIN` 从列表打开任意任务的执行历史并复制会话 ID；`USER_A` 尝试直接调用管理端接口（概览、列表、强制启停、任意任务执行历史）。
- 预期：管理端执行历史字段与用户侧完全一致（状态、来源、会话、计划时间、完成时间、耗时、Agent Run、错误信息），可跨用户查看；`USER_A` 与 `NO_SCOPE_USER` 调用 `/admin/agent-schedules/**` 一律被拒绝（不是仅隐藏入口），且不返回其他用户的任务数据；用户侧 `/agent-schedules` 只能看见自己的任务，不能通过改 `job_id` 读取他人任务或执行历史。
- 边界：管理端执行历史为空显示「暂无执行记录」；越权被拒时页面不把拒绝显示为成功。
- 关联：`AgentScheduleAdminPanel.vue`、`AgentScheduleRunsTable.vue`；`GET /admin/agent-schedules/{job_id}/runs`；SYS-03 普通与 admin 接口分离。

#### SCHED-08 定时任务端到端触发与结果交付

- 角色：`USER_A`
- 前置：准备一个单次任务，执行时间设为近未来 2~5 分钟，绑定一个历史会话并配置可成功查询的数据源组；另准备一个绑定会话已删除、以及一个数据源组被删/无权限的任务。
- 操作：等到点后观察绑定会话是否产生新轮次；打开任务「执行历史」与「立即执行」核对；打开绑定会话核对问答内容与结果文件；分别对异常任务等到点或在会话正忙时立即执行。
- 预期：到点后任务在绑定会话内自动执行一次智能问数，会话中出现新的用户指令轮次与回答，查询结果按统一 `results[]` 落盘到 `outputs/query_result`（口径同 RUN-04）；执行历史新增一条来源为「计划」的记录，状态与 Agent Run 状态一致；绑定会话已删除时执行历史给出可读失败原因而不是静默丢弃；数据源组无权限/不存在时同样落到可读失败；「每次新建会话」模式每次触发新建一个会话并把结果留在新会话中，不往同一个会话叠加；**定时轮无人值守不装配 `ask_user_question`**：执行全程不出现「等待用户回答」的提问交互（即使指令里明确要求向用户提问，模型也只能收到工具不存在的错误提示后自行改道继续）。
- 边界：调度器重启或任务到点时系统繁忙，不应产生重复执行；已停用/已删除任务不再触发；同一次触发只产生一条执行记录。
- 关联：SCHED-02/04；AG-06 结果落盘；RUN-04 结果交付；`agent/run/agent_schedule_runtime.py`、`services/agent_schedule/`。
