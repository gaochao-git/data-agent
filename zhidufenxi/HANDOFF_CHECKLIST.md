# 交接验收清单

## 1. 代码落点

新会话中的实现代码需要满足：

- 单独一个文件夹
- 可直接命令行运行
- 不依赖 Web 接口

## 2. 最低可用能力

完成后至少应满足：

- 能读取 `document_catlog.json`
- 能递归查找 PDF
- 能抽出制度正文
- 能切分出 `第X条`
- 能输出 `documents.jsonl`
- 能输出 `clauses.jsonl`
- 能输出 `errors.jsonl`

## 3. 验收样例

至少人工抽查 3 份 PDF，确认：

1. 前 1 到 2 页说明性内容未被大面积纳入正文
2. `第一章 / 第一条` 开始的正文被成功保留
3. 尾部附表、清单没有大面积混入正文
4. `第X条` 条号切分正确
5. 每条 `article_text` 可读且连续

## 4. 风险点

实现时重点关注：

- 有些 PDF 可能没有显式 `附件`
- 有些制度可能直接从 `第一条` 开始
- 有些附表标题可能出现在正文中，尾部截断不要过早
- 同名 PDF 可能存在多个路径，需要按分类优先匹配
- 提取文本时不能把所有换行都抹掉

## 5. 建议优先顺序

先保证：

1. 正文抽取可用
2. 条款切分可用
3. 输出结构清晰

再考虑：

1. 页码映射更准确
2. 条内分项更细
3. 边缘 PDF 兼容性

## 6. 下一步接口预留

完成后，后续冲突分析脚本可以直接消费 `clauses.jsonl`。

建议后续字段预留方向：

- `topic`
- `subject`
- `action`
- `modality`
- `approval_role`
- `time_limit`
- `amount_limit`

但本次不要实现这些字段。
