# 实现规格

## 1. 目标

实现一个批处理脚本，读取：

- `document_catlog.json`
- PDF 根目录

然后输出：

- 每份制度的正文文本
- 每份制度切分后的条款结果

## 2. 推荐脚本名称

```bash
extract_pdf_clauses.py
```

## 3. 推荐命令行参数

```bash
python extract_pdf_clauses.py \
  --catalog-json /data/aigc/zhidu/document_catlog.json \
  --pdf-dir /data/aigc/zhidu/pdf \
  --output-dir /tmp/zhidu_extract
```

建议支持：

- `--catalog-json`
- `--pdf-dir`
- `--output-dir`
- `--category`
- `--limit`
- `--debug`

## 4. 输入假设

### 4.1 目录 JSON

顶层是对象：

- key 为分类名
- value 为该分类下 PDF 文件名列表

### 4.2 PDF 目录

PDF 目录可能是：

- 平铺
- 按分类分子目录
- 多级目录

因此脚本需要支持：

- 递归扫描 PDF 根目录
- 通过文件名查找 PDF
- 若文件名重复，优先匹配包含分类名的路径

## 5. 正文抽取规则

### 5.1 正文开始

优先识别以下锚点：

- `附件`
- `第一章`
- `第一条`

处理策略：

- 逐页读取文本
- 扫描第一页到最后一页
- 发现第一个开始锚点后，作为正文起点
- 若一页中前半段是说明、后半段开始正文，则从命中位置截断

### 5.2 正文结束

优先识别以下尾部锚点：

- `附表`
- `目录清册`
- `移交清单`
- `登记表`
- `审批表`
- `流程图`
- `附录`

处理策略：

- 从正文起点向后扫描
- 为避免误截断，建议在已识别到若干个 `第X条` 之后，再启用尾部截断
- 若未识别到尾部锚点，则保留到文档结束

## 6. 文本清洗规则

建议做以下清洗：

- 统一换行符为 `\n`
- 去除 BOM
- 压缩连续空格
- 去掉明显空白行
- 尽量保留章、条前后的换行

注意：

- 不要把全文压成一行
- 不要删除所有换行，否则后续切条会不稳定

## 7. 条款切分规则

### 7.1 第一版切分层级

第一版建议切到：

- `章`
- `条`
- 可选 `（一）（二）（三）`

最小分析单元以 `第X条` 为主。

### 7.2 推荐正则

章节：

```python
r"(?m)^\\s*(第[一二三四五六七八九十百千零〇\\d]+章)\\s*([^\\n]*)"
```

条款：

```python
r"(?m)^\\s*(第[一二三四五六七八九十百千零〇\\d]+条)\\s*([^\\n]*)"
```

条内款项：

```python
r"(?m)^\\s*([（(][一二三四五六七八九十百千零〇\\d]+[)）])\\s*([^\\n]*)"
```

### 7.3 切分建议

先分章，再分条。

每条需要至少保留：

- 所属文档
- 所属分类
- 章号
- 章标题
- 条号
- 条文全文
- 条内款项列表

## 8. 输出文件设计

### 8.1 documents.jsonl

每行一个文档对象，建议字段：

```json
{
  "doc_id": "zd_xxx",
  "category": "采购管理",
  "title": "采购管理办法",
  "file_name": "采购管理办法.pdf",
  "file_path": "/data/aigc/zhidu/pdf/采购管理办法.pdf",
  "total_pages": 18,
  "body_pages": [3, 4, 5, 6],
  "body_page_count": 4,
  "start_anchor": "第一章",
  "end_anchor": "附表",
  "body_text_length": 12035,
  "clause_count": 36
}
```

### 8.2 clauses.jsonl

每行一个条款对象，建议字段：

```json
{
  "doc_id": "zd_xxx",
  "category": "采购管理",
  "title": "采购管理办法",
  "file_name": "采购管理办法.pdf",
  "file_path": "/data/aigc/zhidu/pdf/采购管理办法.pdf",
  "chapter_no": "第一章",
  "chapter_title": "总则",
  "article_no": "第一条",
  "article_text": "第一条 为规范采购行为......",
  "items": [
    "（一）......",
    "（二）......"
  ],
  "source_pages": [3]
}
```

### 8.3 errors.jsonl

用于记录：

- PDF 未找到
- PDF 无法解析
- 正文为空
- 条款切分失败

## 9. 依赖建议

优先级如下：

1. `PyMuPDF`
2. `pypdf`

说明：

- 这一步不需要 OCR
- 这一步不需要大模型

## 10. 推荐实现步骤

1. 读 `document_catlog.json`
2. 递归扫描 PDF 根目录并建索引
3. 逐个定位 PDF 文件路径
4. 逐页抽文本
5. 定位正文开始与结束
6. 拼接正文文本
7. 按章条切分
8. 写出 `documents.jsonl`
9. 写出 `clauses.jsonl`
10. 写出 `errors.jsonl`

## 11. 推荐日志内容

至少打印：

- 总文件数
- 已处理文档数
- 当前处理文件名
- 当前文档切出条款数
- 错误数

## 12. 明确不做的事情

本次实现中不要额外加入：

- 冲突分析逻辑
- 大模型调用
- 复杂回退策略
- 业务规则扩展

先把“正文抽取 + 条款切分”做稳定即可。
